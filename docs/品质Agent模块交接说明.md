# 品质数据处理 Agent 模块交接说明

## 1. 使用对象和目的

本说明发给原竹丝水分、水煮实验、售后三个模块的负责人。目的是确保三个模块能够被统一品质Agent直接安装、调用、测试和升级，避免最终通过复制代码或人工修改才能合并。

每位负责人交付的不是“一个演示程序”，而是一个边界明确、可独立运行、可被统一框架调用的模块包。

## 2. 强制交接形式

每个模块必须交付一个完整文件夹或ZIP压缩包，名称格式为：

```text
<module_id>-<version>.zip
```

模块编号固定为：

- `moisture`：原竹丝水分检测；
- `boiling`：水煮实验；
- `after_sales`：售后统计。

例如：

```text
moisture-0.1.0.zip
```

模块必须能够通过命令行无人工点击运行：

```text
<模块启动命令> run --job <job.json路径>
```

不接受以下形式作为正式交付：

- 只交付一段聊天记录或零散代码；
- 只能在开发者电脑上运行；
- 必须手动打开源代码修改路径；
- 必须复制粘贴到总框架内部才能运行；
- 只有界面，没有可自动调用入口；
- 未提供依赖、测试样本或使用说明。

## 3. 标准模块包目录

```text
<module_id>/
├─ module.json                 # 模块身份、版本和启动信息
├─ README.md                   # 安装、运行、输入输出和限制
├─ CHANGELOG.md                # 版本修改记录
├─ requirements.txt            # Python依赖；非Python提供等价依赖清单
├─ run_module.bat              # Windows统一启动脚本
├─ src/                        # 模块源代码
├─ rules/
│  └─ default_rules.yaml       # 默认规则、阈值和分类词典
├─ templates/                  # 输出Excel和报告模板
├─ schemas/                    # 模块内部字段定义
├─ samples/
│  ├─ input/                   # 脱敏输入样本
│  └─ expected/                # 对应预期结果
├─ tests/                      # 自动测试或可复现测试脚本
├─ docs/
│  ├─ 字段映射表.md
│  ├─ 计算公式与判定规则.md
│  ├─ 人工确认边界.md
│  └─ 已知限制.md
└─ example_output/             # 一次完整示例输出
```

不得在包内提交真实客户隐私、银行账户、未脱敏联系人、商业敏感数据或个人密钥。

## 4. module.json要求

每个模块提供如下信息：

```json
{
  "schema_version": "1.0",
  "module_id": "moisture",
  "module_name": "原竹丝水分检测",
  "module_version": "0.1.0",
  "entrypoint": "run_module.bat",
  "healthcheck_command": "run_module.bat self-check",
  "supported_extensions": [".xlsx"],
  "supports_single_file": true,
  "supports_batch": true,
  "supports_incremental": true,
  "requires_network": false
}
```

字段不得省略。若需要网络、商业API、模型文件或授权，必须如实声明，并在README中说明无网络时的行为。

## 5. 统一任务输入协议

框架通过 `job.json` 向模块传递任务：

```json
{
  "schema_version": "1.0",
  "job_id": "20260712-0001",
  "module_id": "moisture",
  "run_mode": "batch",
  "input_files": [
    "D:/data/input/example.xlsx"
  ],
  "output_dir": "D:/data/output/20260712-0001",
  "config_file": "D:/data/config/moisture.yaml",
  "locale": "zh-CN"
}
```

模块必须遵守：

- 只处理 `input_files` 中明确列出的文件；
- 不修改、重命名或删除原文件；
- 不把输入路径、输出路径或用户名硬编码；
- 所有成果写入 `output_dir`；
- 缺少配置时使用模块包内默认规则，并在结果中记录规则版本；
- 单个文件失败时继续处理其他文件，并在结果中报告失败项。

## 6. 统一结果协议

模块必须在输出目录生成 `result.json`：

```json
{
  "schema_version": "1.0",
  "job_id": "20260712-0001",
  "module_id": "moisture",
  "module_version": "0.1.0",
  "status": "needs_confirmation",
  "rule_version": "2026.07",
  "summary": {
    "input_count": 10,
    "processed_count": 9,
    "skipped_count": 1,
    "failed_count": 0,
    "anomaly_count": 2,
    "confirmation_count": 1
  },
  "anomalies": [],
  "confirmations": [],
  "outputs": [],
  "file_results": [],
  "errors": [],
  "started_at": "2026-07-12T15:00:00+08:00",
  "finished_at": "2026-07-12T15:00:15+08:00"
}
```

允许的任务状态只有：

- `success`：全部成功且无待确认项；
- `partial_success`：部分文件失败或跳过，但已生成有效结果；
- `needs_confirmation`：已完成自动处理，存在必须人工确认的事项；
- `failed`：无法形成有效结果。

### 6.1 异常对象

```json
{
  "anomaly_id": "A-001",
  "source_file": "example.xlsx",
  "sheet": "Sheet1",
  "cell_or_range": "G4",
  "field": "total_average_moisture",
  "value": 0.4688,
  "severity": "warning",
  "rule_id": "MOISTURE-BAND-001",
  "message": "总平均含水率低于暂定正常区间",
  "suggestion": "复核取样位置、烘干时间和称量记录"
}
```

异常等级固定为：

- `info`：提示，不影响统计；
- `warning`：需要关注或复核；
- `critical`：计算错误、关键数据缺失或高风险异常。

### 6.2 人工确认对象

```json
{
  "confirmation_id": "C-001",
  "source_file": "example.xlsx",
  "field": "product_usage",
  "reason": "原文件未提供产品用途，无法选择膨胀率标准",
  "suggested_value": null,
  "options": ["地板", "家具", "墙板", "栏杆", "其他"],
  "confidence": 0.0,
  "blocking": true,
  "batch_applicable": true,
  "rememberable": true
}
```

原则：能自动提取的不得要求人工重复输入；只有缺失、冲突、低置信度或必须由人员承担责任的结论才能进入 `confirmations`。

### 6.3 输出文件对象

```json
{
  "type": "summary_excel",
  "path": "D:/data/output/20260712-0001/moisture_summary.xlsx",
  "label": "水分检测月度汇总",
  "mime_type": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
}
```

### 6.4 单文件结果

每个输入文件必须有对应记录，至少包含：

- 来源文件；
- 文件指纹或唯一标识；
- 处理状态；
- 提取记录数；
- 缺失字段；
- 异常数量；
- 使用的规则版本；
- 错误信息；
- 可选的来源工作表和单元格位置。

框架必须能够据此核对是否漏读或重复处理。

## 7. 命令和退出码

每个模块至少支持：

```text
run_module.bat self-check
run_module.bat run --job <job.json路径>
run_module.bat version
```

退出码约定：

- `0`：模块成功生成结构合法的 `result.json`，包括部分成功或待确认；
- `2`：任务JSON不合法；
- `3`：模块运行失败，无法生成有效结果；
- `4`：依赖、模型或运行环境缺失。

模块不得用弹窗代替错误返回。错误需要同时写入标准错误输出和 `result.json`；若无法生成结果，则至少返回明确退出码和可读错误信息。

## 8. 三个模块的最低业务交付

### 8.1 moisture模块

必须实现：

- 识别供应商、到货日期、检测日期、总重和取样部门；
- 提取初始质量、烘干质量、锡纸质量；
- 计算并复核单样含水率、部门平均值和总平均值；
- 兼容二厂、品质各3个或4个样品；
- 批量汇总并按日期排序；
- 根据配置规则标记异常；
- 生成汇总Excel、趋势图和异常分析；
- 忽略临时文件和识别重复文件；
- 异常原因只给复核建议，不直接断言。

最低测试样本：正常表、低值表、高值表、6样品表、缺字段表、重复文件。

### 8.2 boiling模块

必须实现：

- 提取产品、规格、压制日期、班长、检测日期、浸胶日期和订单信息；
- 复核平均厚度、体积、密度、密度差和膨胀率；
- 提取浸渍剥离合格/不合格文字；
- 兼容不同试件数量和表格结构；
- 区分正常、异常、信息不足和待人工确认；
- 原表结论与规则复核冲突时保留两者并提示复核；
- 产品用途缺失时不得擅自选择膨胀率标准；
- 生成汇总Excel、图表和异常分析；
- 空表、未完成表不得进入正常统计。

最低测试样本：全合格、密度异常、膨胀率异常、浸渍剥离异常、复测、不同试件数量、空表或未完成表。

### 8.3 after_sales模块

必须实现：

- 识别不同售后模板和同义字段；
- 提取客户、地点、销售、产品、规格、订单、日期和反馈；
- 提取售后调查、方案、费用、责任和审批/关闭信息；
- 推荐品牌和性能、外观、加工等问题类型；
- 支持一案多问题或人工修改分类；
- 区分实际费用、预估费用、申请费用和不纳入统计的费用；
- 责任和关闭状态不明确时必须请求人工确认；
- 生成月度、年度汇总、品牌占比、问题占比、责任费用和关闭统计；
- 对低置信度分类提供候选项和证据来源。

最低测试样本：标准模板、同义字段模板、多费用、多问题、多责任、未关闭、缺字段和重复文件。

## 9. 规则和人工判断边界

每个模块必须把规则分为：

1. 明确公式：可自动执行；
2. 客户确认阈值：可自动比较，规则可配置；
3. 经验建议：只用于提示；
4. 权限性结论：必须人工确认。

所有阈值和分类映射必须有规则编号、版本、适用范围和来源说明。未经确认的暂定规则不得伪装成正式标准。

## 10. 自测和预期结果

每个模块负责人提交前必须：

- 运行 `self-check`；
- 对全部脱敏样本运行一次；
- 提供每个样本的预期结构化结果；
- 核对核心字段和公式；
- 扫描输出Excel公式错误；
- 验证重复运行不会重复统计；
- 验证原始文件未被修改；
- 验证单个坏文件不会导致整批失败；
- 记录仍未支持的情况。

核心字段、公式和标准样本结果必须100%符合预期，才能提交集成。

- 需要客户确认的业务规则。

## 12. 接收方验收顺序

接收模块后按照以下顺序处理：

1. 检查交付包目录和必需文件；
2. 检查是否包含敏感数据或密钥；
3. 在干净环境中安装依赖；
4. 运行 `version` 和 `self-check`；
5. 运行模块自带样本；
6. 核对预期结果；
7. 使用项目历史样本复测；
8. 校验 `result.json`；
9. 接入统一框架；
10. 运行统一入口端到端测试；
11. 登记问题并退回修改；
12. 修复后回归测试并确认版本。

## 13. 正式接入门槛

满足以下条件才允许接入主框架：

- 模块包完整；
- 能在干净环境安装；
- 三条强制命令可运行；
- 输入输出协议符合本说明；
- 标准样本核心结果100%正确；
- 不修改原始文件；
- 重复运行不重复统计；
- 所有结果可追溯；
- 错误和待确认事项结构化返回；
- 没有硬编码绝对路径、账号、密钥或客户隐私；
- 已知限制已经书面说明；
- 严重级问题为零。

不满足门槛的模块退回负责人修改，不通过在总框架内临时打补丁掩盖模块问题。
