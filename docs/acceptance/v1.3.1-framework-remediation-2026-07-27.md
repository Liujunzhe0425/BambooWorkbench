# BambooWorkbench v1.3.1 框架整改实现记录

日期：2026-07-27

分支：`agent/v1.3.1-framework-remediation`

基线：`integration@b89d5f4d6ebcff73f386ed791a7a0cb017bf35ab`

中央正式版本仍为 v1.3.0；本分支不修改版本、main、标签、安装包或 Release。

## 已完成

### 小窗与高 DPI

- 任务创建页和知识库页使用与系统设置一致的纵向滚动页面壳层；
- 外层继续保持统一 30px 页面边距；
- 小窗口出现纵向滚动，禁止横向滚动；
- 输入框、下拉框和按钮不再被布局压缩到文字裁切。

### 月度 finalize 状态

- 带年月、声明月度能力且模块状态为 `success` 或 `partial_success` 的 finalize 强制要求快照；
- `failed`、`cancelled` 不再因为快照为空而覆盖模块原始状态；
- 非成功结果不得携带快照；
- TaskService 对规范化后的成功结果再次执行快照不变量检查；
- 模块失败错误保存到任务记录，并继续由结果页显示；
- 只有 `success/partial_success + 合法快照` 才会进入正式月度累计事务。

### 历史数据页

- 年份支持 2000—2077，默认当前年份；
- 默认内容宽度使用四列，小窗口降为三列或两列；
- 列数变化时清除旧行列伸缩，空列不再占宽；
- 月份卡片横向和纵向填充网格，保持 104px 最小高度；
- 三个模块切换按钮增加明确的选中高亮；
- 未创建月份继续禁用，已创建月份保持可打开完整结果。

## 自动更新凭据边界

现有设置页、Windows 凭据管理器保存、删除令牌、Release 检查、digest 校验和安装流程无需代码修改。当前安装环境没有 `github-updates` 凭据；GitHub CLI 的现有令牌权限大于更新所需权限，框架不静默复制它，也不把令牌写入安装包。

团队测试仍需用户提供仅限本仓库 `Contents: read` 的细粒度令牌，再保存到 `BambooWorkbench / github-updates` 并执行私有 Release 检查。客户更新继续要求公开二进制源或 HTTPS/CDN。

## 模块后续接线

- 水分修复私有快照业务 ID 后，失败结果应变为 `success + snapshot`；
- 水煮修复确认集合漂移后，成功结果必须提供 snapshot；
- 售后在 draft 阶段处理目标年月冲突，零匹配月份不得进入 finalize 正式事务；
- 三个模块最终 PR 在交付前必须同步包含本框架修复的最新 integration，并重新运行正式链路。
