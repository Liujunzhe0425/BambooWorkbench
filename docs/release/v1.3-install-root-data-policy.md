# v1.3 安装根数据与更新保留策略

v1.3 冻结安装版以 `BambooWorkbench.exe` 所在目录为唯一应用根，不再把新任务数据静默写入 `%LOCALAPPDATA%\BambooWorkbench`，也不迁移 v1.2 数据。

## 首次实例

`.bamboo-install.json` 不存在时，框架视为全新实例：

- 清理可能随安装残留的数据库、任务、知识学习、模块数据、缓存和日志；
- 清除已知 AI Provider 密钥与 GitHub 更新令牌；
- 保留安装目录中已经存在的 `source` 和 `output` 用户文件；
- 创建空数据库、实例标记、`source` 三个模块子目录和 `output`；
- 默认 AI 联网为拒绝。

损坏的实例标记不会被当作“全新安装”处理，应用会停止并提示，避免误清理用户数据。

## 覆盖更新与原目录重装

实例标记存在时，程序保留 source、output、数据库、任务快照、知识学习、模块数据、设置和 Windows 凭据。安装器只覆盖登记的程序二进制和静态资源。

卸载仅额外删除 `cache` 和普通 `logs`；`.bamboo-install.json`、`source`、`output`、`data`、`tasks`、`knowledge`、`module-data` 和 Windows 凭据保留。

## 成果恢复

每个正式结果文件夹含隐藏/只读 `.bamboo-task.json`，只记录任务身份、模块、年月、替换事务、快照摘要以及用户成果的相对路径、大小和 SHA-256。它不记录密钥、客户原文、源 Excel 内容或绝对输入路径。

启动时框架读取 `data/output-roots.json`，扫描默认和历史成果根第一层的合法清单，不解析业务 Excel。成果缺失、哈希不符或正式链冲突时标记异常并禁止打开，不自动删除正式月份、内部快照或学习贡献。

## 自动更新边界

已安装客户端能够在启动时发现正式 Release、提示用户、下载、校验 digest、覆盖安装并重启，用户不需要手动下载每个新安装包。开发团队每次要分发新的程序代码时，仍必须构建与版本匹配的安装包并发布 Release（或未来批准的公开二进制更新源）；客户端无法在没有新二进制制品的情况下更新代码。
