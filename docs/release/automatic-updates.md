# BambooWorkbench 自动更新机制

## 更新源

Windows 安装版固定读取公开主仓库的最新正式 Release：

`https://github.com/Liujunzhe0425/BambooWorkbench/releases`

客户端匿名访问，无需 GitHub Token，也不会读取或发送历史版本保存过的更新令牌。Release 必须包含名称与版本匹配的 Windows 安装包，并由 GitHub 返回可校验的 SHA-256 digest。

## 用户流程

安装版启动约 1.5 秒后异步检查更新。没有更新时不打扰用户；发现新版本时显示当前版本和目标版本，由用户决定是否下载。用户同意后：

1. 显示下载进度、百分比、已下载大小和总大小；
2. 下载主仓库 Release 中与目标版本严格匹配的安装包；
3. 复核文件大小和 GitHub Release 提供的 SHA-256；
4. 将安装包及更新辅助程序暂存到系统临时目录；
5. 退出竹简工作台，显式覆盖当前安装目录；
6. 校验三个业务模块均已升级到目标版本；
7. 自动重启竹简工作台。

更新检查、下载或安装失败不会阻止离线业务模块继续使用。辅助程序会记录更新日志，并在失败时尝试重新打开原有程序。

## 安全与数据边界

- 只接受 HTTPS 和固定 GitHub 下载域名；
- 安装包文件名必须与 Release 语义版本完全一致；
- Release 必须提供 `sha256:` digest，大小或哈希不一致时拒绝安装；
- 更新必须由用户确认，不在后台静默安装；
- 安装包与辅助程序在安装目录外运行，避免更新时覆盖自身；
- 覆盖安装保留安装根目录中的 `source`、`output`、数据库、任务快照、知识学习、模块数据、设置、安装实例标记和 Windows 凭据；
- 安装包不包含 GitHub Token、AI API Key、客户文件或历史任务；
- 正式企业部署可进一步为安装包和主程序配置 Windows Authenticode 代码签名。

## 源码运行

源码运行默认不自动检查更新，避免开发测试误覆盖已安装版本。系统设置仍可发起手动检查；如需测试源码检查流程，可设置：

```powershell
$env:BAMBOO_ENABLE_SOURCE_UPDATE_CHECK = "1"
```

## 发布验收要求

1. 标签、产品版本、三个模块版本和安装包名称完全一致；
2. Release 为正式发布而非 Draft 或 Pre-release；
3. Release 安装包资产包含 SHA-256 digest；
4. 未配置任何 GitHub Token 时可以发现、下载并校验更新；
5. 下载进度能持续更新并最终到达 100%；
6. 覆盖安装使用当前安装目录，安装后自动重启；
7. 更新后本地任务、设置、API Key、知识库和历史结果保持不变；
8. 断网、错误哈希、下载中断或安装失败时，离线业务仍可使用。
