# BambooWorkbench v1.3.0 年度滚动、知识自学习与本地数据治理设计

日期：2026-07-26  
状态：已完成逐节口头确认，等待用户审阅书面规格  
目标版本：v1.3.0  
目标平台：Windows  
框架基线：v1.2.0 / `main@2e905f3b9ede4b9643f1e1db9aa869629b0ce38a`  
前置修复：PR #61，`agent/fix-settings-small-window -> integration`，提交 `e6b87b8`

## 1. 目标

v1.3.0 在不改变既有四方责任边界的前提下完成以下产品能力：

1. 三个模块按“模块 + 年 + 月”维护唯一正式月度结果，并生成截至该月的一整套年度累计成果。
2. 提供按年份和模块切换的十二月历史数据页面。
3. 将人工确认结果转化为模块隔离、离线、可解释、可撤销的用户偏好证据。
4. 将除 API Key 外的全部新运行数据改为保存在用户选择的安装根目录；v1.3.0 不迁移 v1.2.0 的旧 C 盘数据。
5. 统一 `source` 输入目录、`output` 成果目录、任务结果文件夹和输出恢复清单。
6. 增加待确认清单、确认草稿恢复和按任务控制是否参与知识学习的能力。
7. 增加凭据删除、默认联网策略和售后模块已验证配置自动跳过配置页。
8. 建立框架、水分、水煮、售后四条独立交付轨道，允许模块负责人同时交付合理的自有更新。

## 2. 非目标与责任边界

本轮不要求框架判断以下内容是否符合客户业务预期：

- Excel 字段映射和原始文件业务解释；
- 水分、水煮、售后的公式、阈值、等级、分类和统计口径；
- 模块报告文字、图表指标和业务记录内容是否正确；
- 模块负责人自行提出的合理业务优化是否属于本轮指定需求。

框架只负责公开合同、任务编排、月度索引、数据路径、恢复、安全、UI 和进程边界。模块业务结果继续由对应负责人承担。

模块负责人可以在 v1.3.0 中增加本轮清单之外的模块功能或修复。框架验收应判断其合理性、测试、合同兼容和安全边界，不得仅因“不是框架指定任务”而退回。需要新增框架能力时，模块必须提交独立 FCR。

## 3. 已确认的产品决策

### 3.1 正式月度结果

- 三个模块都必须支持年度累计滚动，并且彼此独立。
- 每个模块、每个自然年、每个月只有一个当前正式结果。
- 创建任务时必须选择年份和月份，默认当前年月。
- 模块校验输入 Excel 的年月；冲突进入人工确认，不静默改写。
- 允许月份缺口。例如没有 2 月时，3 月累计结果可以由 1 月和 3 月组成。
- 用户每月只看到一套截至该月的完整累计成果，不额外生成“仅本月成果”。
- 重新创建已有正式结果的月份时，在运行前提示替换影响。
- 新任务及所有受影响月份重算成功后才原子替换旧正式结果。
- 任一重算失败时正式索引完全不变，新任务保留为替换候选。

### 3.2 成果与任务名称

- 默认任务名称为“模块名-年份月份”，例如“竹丝水分-2026年03月”。
- 创建任务时允许用户修改任务名称。
- 成果文件夹不使用任务编号。
- 文件夹名固定为 `任务名称-YYYYMMDD-HHMMSS`；非法字符安全替换，冲突时追加短后缀。

### 3.3 自学习

- 所有最终人工选择都可成为学习证据；一致选择强化原建议，不一致选择强化用户选择。
- 三个模块严格隔离，不能跨模块共享偏好。
- 相似情境只使用模块提供的脱敏结构化上下文，不使用 AI、Embedding 或原始文本相似度。
- 学习只调整待确认事项的偏好建议，不修改批准规则、公式、阈值，也不取消人工确认。
- 每个任务在确认页面提供“用于知识库更新”开关，默认开启。
- 只有 finalize、累计渲染和正式结果提交全部成功后证据才生效。
- 替换或移除正式任务时撤销旧任务贡献。
- 支持查看权重、撤销单条证据、重置场景和重置模块全部偏好。

### 3.4 AI 联网

- 全新安装默认拒绝 AI 联网。
- 默认允许时三个模块不再逐任务询问，但仍脱敏并记录授权审计。
- 默认拒绝时水分和水煮自动离线降级。
- 默认拒绝时售后仍逐任务询问；拒绝则不创建售后任务。
- 售后全局配置、密钥和完全相同配置的连接验证都有效时，进入模块直接跳过配置页。

## 4. 总体架构

采用“框架月度台账 + 模块累计渲染合同”。

```text
本月 Excel
  -> 模块 draft
  -> 人工确认
  -> 模块 finalize
  -> 不可变月度结构化快照
  -> 框架登记候选
  -> 模块累计渲染
  -> 完整累计成果与输出清单
  -> 框架原子提交正式月度结果
  -> 生效知识学习证据
```

框架不读取模块快照中的业务字段，只校验公共信封、路径、版本、大小和哈希。模块负责校验自己的快照负载并生成业务成果。

## 5. 安装根目录与数据目录

冻结安装版通过 `BambooWorkbench.exe` 所在目录确定根目录。源码开发和测试必须显式提供临时数据根，禁止污染仓库或真实安装目录。

```text
{安装根目录}
├─ BambooWorkbench.exe
├─ .bamboo-install.json
├─ source
│  ├─ 竹丝水分
│  ├─ 水煮模块
│  └─ 售后分析
├─ output
├─ data
│  └─ app.db
├─ tasks
├─ knowledge
├─ module-data
├─ logs
└─ cache
```

API Key 和 GitHub 更新令牌继续保存在 Windows 安全凭据管理器，是唯一不写入安装根目录的运行数据。

安装根目录不可写时，应用必须显示明确错误并停止创建任务；不得静默回退到 C 盘。

### 5.1 v1.3.0 首次启动

`.bamboo-install.json` 不存在时视为全新安装：

1. 不读取、不迁移 `%LOCALAPPDATA%\BambooWorkbench` 中的 v1.2.0 数据。
2. 清除 BambooWorkbench 已知 AI Provider 密钥和 GitHub 更新令牌。
3. 创建新的空数据库、内部数据目录和实例标记。
4. 创建缺失的 `source`、三个模块子目录和 `output`。
5. 已经存在的 `source` 或 `output` 用户文件不得删除、覆盖或移动。
6. 默认 AI 联网策略写为拒绝。

实例标记包含安装实例 ID、创建时间和 Schema 版本，不包含用户信息、路径以外的敏感数据或密钥。

### 5.2 更新、重装和卸载

实例标记存在时视为覆盖更新或原目录重装：

- 保留凭据、设置、数据库、任务快照、知识学习、模块数据、`source` 和 `output`。
- 更新只替换安装器登记的程序二进制和静态资源。
- 安装器不得把用户数据目录登记为普通安装文件或卸载删除目标。

卸载时删除程序二进制、静态资源、缓存和普通日志，保留：

- `.bamboo-install.json`
- `source`
- `output`
- `data`
- `tasks`
- `knowledge`
- `module-data`
- Windows 凭据

## 6. Source 输入目录

框架只创建 `source` 和三个模块子目录，不创建年月目录。用户自行维护年月目录和 Excel。

创建任务时：

- 文件对话框默认定位到当前模块子目录。
- 用户仍需自行进入最终位置。
- 可以批量选择部分受支持 Excel。
- 可以选择整个文件夹，自动加入该文件夹第一层全部受支持 Excel。
- 不递归读取更深子目录。
- 框架只读源文件并创建任务私有快照，不修改、重命名或移动 `source` 内容。

## 7. Output 成果目录与清单

未配置自定义成果根目录时使用 `{安装根目录}\output`。用户修改成果位置只影响新任务成果发布位置，不改变数据库、内部任务、模块数据或文件夹结构。

框架维护“已知成果根目录”列表。该列表除写入数据库外，还原子写入安装根目录下的 `data/output-roots.json`，包含 Schema 版本、当前根和历史根。修改保存位置后，旧根目录仍保留在只读扫描列表中，既有任务继续可打开；新任务只写入当前配置根目录。数据库文件单独丢失时，框架先读取该列表，再扫描默认根和全部已知根。

每个成功结果目录包含模块生成的完整累计成果，以及框架生成的隐藏、只读 `.bamboo-task.json`。清单至少包含：

- 清单 Schema 版本；
- 安装实例 ID；
- 任务 ID、任务名称、模块、年份、月份；
- 任务创建、完成和正式提交时间；
- 月度快照版本与 SHA-256；
- 替换关系和事务 ID；
- 所有用户成果的相对路径、类型、标签、大小和 SHA-256；
- 清单自身的规范化摘要。

清单禁止包含 API Key、Authorization Header、客户原始文本、源 Excel 内容或绝对输入路径。

软件启动时增量扫描默认根和已知根中的清单，不解析业务 Excel。数据库丢失时使用合法清单重建任务历史、输出映射、替换链和月度正式索引。

如果多个清单竞争同一正式月份，只接受可以形成完整、无环替换链且提交时间和事务状态一致的清单；否则标记冲突并要求人工处理，不猜测正式结果。

### 7.1 成果缺失

数据库中已登记目录缺失或清单哈希失败时：

- 任务标记“成果文件缺失”或“成果完整性异常”；
- 禁止打开成果；
- 不自动删除正式月份、内部快照或学习贡献；
- 提供“重新生成成果”和“移除此任务记录”。

移除非正式任务只删除其框架记录和内部候选数据。移除正式任务必须显示受影响月份；用户确认后取消该月正式结果、撤销学习贡献，并事务性重算后续月份。失败时保持原状态。

## 8. 月度数据模型

数据库迁移新增或扩展以下概念：

### 8.1 任务周期

每个根任务记录：

- `task_name`
- `period_year`
- `period_month`
- `learning_enabled`
- `candidate_for_job_id`
- `output_root_id`

数据库对年份和月份执行范围约束，月份必须为 1—12。

### 8.2 正式月份槽位

`monthly_slots` 使用 `(module_id, year, month)` 唯一键，并指向当前正式根任务。槽位切换只能由成功的累计事务完成。

### 8.3 不可变月度快照

`monthly_snapshots` 记录快照路径、模块合同版本、大小、SHA-256、创建任务和状态。已经成为正式结果的快照不可原地修改。

### 8.4 重算事务

`rollup_transactions` 和事务项记录：

- 候选月份；
- 旧、新正式任务；
- 受影响月份集合；
- 每个月的暂存输出、校验和错误；
- `preparing / rendering / validated / committed / failed` 状态。

只有全部事务项 validated 后才能在一个数据库事务内切换正式槽位、输出映射和学习证据。

## 9. 模块累计公开合同

三个模块的 manifest 必须显式声明 `monthly_rollup` 能力和模块自有快照/累计请求响应 Schema。框架不得直接 import 模块 Python 类。

### 9.1 Finalize 输出

普通模块 finalize 除现有业务结果外，增加一个内部月度快照工件：

```json
{
  "schema_version": "1.0",
  "module_id": "moisture",
  "module_version": "1.3.0",
  "year": 2026,
  "month": 3,
  "snapshot_format": "module-owned-v1",
  "payload": {}
}
```

公共信封由框架校验，`payload` 由模块 Schema 校验。快照必须反映最终人工确认后的本月独立业务记录，但不作为用户成果展示。

### 9.2 累计渲染请求

框架按月份升序传入同模块、同年份、月份不大于目标月的全部正式快照，加上当前候选快照。请求包含：

- 模块、年份、目标月份；
- 有序快照文件及哈希；
- 框架授权的暂存输出目录；
- 当前规则、经验或业务配置快照身份；
- 禁止联网标志。

模块必须：

- 拒绝其他模块、其他年份、重复月份、乱序、越界和哈希不一致快照；
- 允许月份缺口；
- 只使用已经确认完成的结构化记录；
- 不读取 API Key，不发送服务请求，不调用 AI；
- 生成与普通结果页一致的一整套累计 Excel、报告、图表和业务记录。

### 9.3 累计响应

响应返回状态、目标年月、使用的月份、快照哈希集合和全部输出工件。框架再次校验后生成 `.bamboo-task.json` 并发布。

## 10. 正式结果与替换流程

### 10.1 首次创建月份

1. 用户选择模块、年月、名称和输入。
2. 模块完成 draft、确认和 finalize。
3. 框架取得月度快照。
4. 模块使用截至目标月已有快照生成累计成果。
5. 框架校验并原子设为正式结果。
6. 学习证据生效。

### 10.2 替换已有月份

任务开始前显示旧正式任务、影响月份和重算范围。用户确认后创建替换候选。

候选 finalize 成功后，框架使用新候选快照替换旧月快照，并为该月及所有已有后续正式月份准备累计成果。全部成功后一次提交：

- 切换候选月份正式任务；
- 更新后续月份输出；
- 撤销旧任务学习贡献；
- 生效新任务学习贡献；
- 将旧任务保留在普通任务历史中。

任一阶段失败时正式状态不变，候选可查看、诊断和重试。

## 11. 历史数据页面

左侧导航新增“历史数据”。页面采用已批准布局：

- 左上角年份选择；
- 中上方三个模块切换按钮；
- 当前模块高亮；
- 下方只显示当前年份和当前模块的十二个月卡片。

状态样式：

- 已创建：浅绿背景、深绿色文字，可点击；
- 重算中：浅黄背景、深棕色文字，事务完成前禁用；
- 未创建：灰色背景和文字，禁用点击，不显示“不可点击”；
- 替换候选：显示候选和失败/重试状态，不冒充正式结果；
- 成果缺失或异常：红色提示并提供治理操作。

小窗和高 DPI 下卡片自适应列数并纵向滚动，不压缩文字和控件。

点击已创建月份直接进入正式任务的结果页面，列出该结果目录中的全部累计成果。

## 12. 待确认清单与草稿

左侧“待确认”改名为“待确认清单”。清单只展示状态为 waiting_confirmation 的根任务，跨模块按创建时间倒序，显示：

- 任务名称和任务 ID；
- 模块；
- 年份和月份；
- 创建时间；
- 待确认数量。

进入任务后加载确认页面。用户每次修改答案后，框架原子保存 `confirmation_draft`。草稿跨页面返回和软件重启恢复，但不写入正式确认文件、不触发 finalize、不参与学习。

确认页统一增加默认开启的“将本次最终选择用于知识库更新”开关，并随草稿保存。

未提交时返回待确认清单。提交后清除草稿，进入生成进度页；成功后自动进入结果页并从待确认清单移除。

## 13. 知识自学习合同

### 13.1 优先级

```text
已批准规则 / 公式 / 阈值
  > 模块确定性判断
  > 用户偏好证据
  > AI 通用建议
```

### 13.2 模块学习描述

可学习的确认项增加可选、版本化 `learning` 描述：

- `learning_key`
- `field`
- `context`
- `context_levels`
- 稳定候选 ID 和用户显示文本
- `base_suggestion`
- `preference_adjustable`

模块必须确保上下文脱敏、结构化且稳定。自由文本、客户身份、绝对路径和原始单元格不得进入学习描述。

非枚举或不适合学习的确认项省略该描述，框架不得自行推断场景。

### 13.3 权重规则

- 每条正式最终答案对选择的候选贡献 1 个权重单位。
- 所有选择都记录，包括与基础建议一致的答案。
- 从最精确上下文开始匹配；当前层级有证据时不再向更宽层级混加。
- 当前层级最高权重候选成为偏好建议。
- 权重并列时使用模块基础建议。
- 不使用时间衰减。
- 框架只有在 `preference_adjustable=true` 且偏好候选属于模块允许集合时，才调整 UI 默认建议。
- 最终业务值始终来自人工答案。

### 13.4 生效与撤销

证据必须同时满足：

- 任务学习开关开启；
- finalize 成功；
- 累计事务成功；
- 任务成为正式月度结果。

替换、移除、单条撤销和重置通过可审计失效记录使证据不再计权，不物理篡改历史。

知识库页面按模块展示场景、上下文、候选权重、当前偏好、来源任务、年月和状态，支持：

- 撤销单条证据；
- 重置场景；
- 重置模块全部偏好。

所有写操作二次确认，并明确不影响批准规则。

## 14. AI 凭据与联网策略

### 14.1 凭据验证身份

每次保存或删除 Provider 密钥时生成新的随机 `credential_revision`。数据库只保存 revision，不保存密钥哈希。成功验证记录绑定：

```text
provider_id + base_url + model + credential_revision
```

任一字段变化都使验证失效。

系统设置分别提供：

- 删除当前 AI Provider 密钥；
- 删除 GitHub 更新令牌。

删除 Provider 密钥时同时取消其验证状态；两类凭据互不影响。

### 14.2 默认允许

三个模块不显示逐任务授权操作。框架仍执行脱敏、审计和最小数据类别限制。任务详情展示数据类别、脱敏摘要和授权来源，不展示密钥或模型原始敏感响应。

### 14.3 默认拒绝

- 水分、水煮 AI 请求自动返回 denied 并离线降级。
- 售后每个任务单独询问本批次授权；拒绝时不创建任务。

### 14.4 售后入口

配置字段完整、凭据存在且相同 revision 的相同配置已成功测试时，售后入口直接进入任务创建页。配置缺失、变化、删除或验证失效时才进入售后 AI 配置页。

任务启动后的超时、限流、模型错误和无效响应继续安全降级，不跳回配置页，不丢失输入对账，不在累计渲染或 finalize 阶段重复联网。

## 15. 安全和权限边界

- 模块进程不得读取 Windows 凭据或直接访问 Provider。
- 累计渲染进程强制离线。
- 月度快照、输出清单、学习上下文和日志不得包含密钥、Header、客户原文或绝对输入路径。
- 所有外部或模块返回路径执行包含性、符号链接、junction 和越界校验。
- 输出先写暂存目录，校验后通过同卷原子重命名发布；跨卷自定义输出根使用复制、fsync、校验、最终重命名流程。
- 清单和快照采用 SHA-256 完整性校验；SHA-256 用于完整性，不用于身份认证或凭据处理。
- 模块错误以稳定错误码进入框架，不显示 traceback、临时路径或环境变量。

## 16. 异常处理

### 16.1 累计失败

失败事务保留诊断状态和候选，不切换正式槽位、不更新学习、不覆盖成果。

### 16.2 应用中断

启动恢复时检查事务状态：

- preparing/rendering：验证暂存目录后标记中断并允许重试；
- validated 但未 committed：重新执行幂等提交或回滚；
- committed：核对数据库、清单和正式目录一致性。

### 16.3 数据库丢失

从合法输出清单恢复可见历史和正式月份索引。内部确认草稿、未发布候选和没有写入 output 的运行中任务无法仅靠成果清单恢复，应明确标记为不可恢复，而不是伪造状态。

### 16.4 输出根不可用

新任务不得在用户不知道的情况下回退到其他磁盘。框架保留内部结果并提示成果发布失败，用户修复路径后可重试发布。

模块自行增加的功能必须在 PR 说明和 Changelog 中列出，并提供测试。框架负责人积极评估和适配合理变更；重大业务问题交回模块负责人，不由框架代为修改业务代码。

## 19. 验收矩阵

### 19.1 月度累计

- 三模块 1 月首次创建。
- 1 月后创建 2 月。
- 缺少 2 月时创建 3 月。
- 三个模块同年月互不影响。
- 跨年不累计上一年。
- 输入年月冲突进入确认。
- 替换 1 月并重算已有后续月份。
- 中途重算失败时正式结果完全不变。
- 候选重试后一次提交成功。
- 累计渲染外部网络调用为 0。

### 19.2 历史和恢复

- 年份与模块共同过滤十二个月卡片。
- 未创建卡片禁用且无“不可点击”文字。
- 小窗、高 DPI 和全屏可用。
- 数据库丢失后从清单恢复历史和正式索引。
- 数据库丢失后从 `data/output-roots.json` 找回自定义成果根并扫描其清单。
- 清单非法、哈希损坏、目录缺失和竞争链冲突安全降级。
- 重新生成和移除正式任务按确认范围执行。

### 19.3 知识学习

- 学习开关默认开和人工关闭。
- 一致、不同选择都增权。
- 精确上下文和逐级回退。
- 权重并列使用模块基础建议。
- 模块隔离。
- 失败、取消、候选任务不学习。
- 替换、移除、单条撤销、场景重置和模块重置。
- 批准规则和公式不改变。

### 19.4 待确认

- 多个跨模块待确认任务按时间倒序。
- 只显示 waiting_confirmation。
- 草稿每次修改后保存并跨重启恢复。
- 草稿不参与学习。
- 返回清单和提交后的进度/结果导航正确。

### 19.5 安装与凭据

- 新根目录首次安装为空数据库、空历史和空凭据。
- 不迁移 v1.2.0 AppData。
- 不删除预先存在的 `source` 和 `output` 用户文件。
- 覆盖更新保留所有重要数据和凭据。
- 卸载删除程序、缓存和普通日志，保留用户数据和实例标记。
- 原目录重装继续识别安装实例。
- 删除当前 Provider 密钥使验证失效。
- 删除更新令牌不影响 AI Key。
- 默认允许、默认拒绝和售后拒绝不创建任务。
- 售后有效配置跳过配置页，配置变化后重新进入。

### 19.6 安全

- Git、日志、数据库、清单、任务、输出和安装包中不存在密钥。
- 学习上下文和清单不存在客户原文或绝对输入路径。
- 路径越界、符号链接、junction 和替换攻击被拒绝。
- 源码、便携版和安装版合同一致。

## 20. 版本和发布

- 设计和开发期间产品正式版本仍为 v1.2.0。
- 模块可在自己的 v1.3.0 PR 中声明目标模块版本，但不能修改中央发布元数据。
- 三模块和框架联合验收通过后，先在 `integration` 进行人工测试。
- 只有用户明确授权正式发布后，才能统一中央和模块版本、合并 `integration -> main`、打 `v1.3.0` 标签、构建安装包并创建 Release。
- v1.2.0 安装版必须完成一次“发现 v1.3.0 -> 用户确认 -> 下载 -> digest 校验 -> 覆盖更新 -> 自动重启 -> 数据保留”验收。
