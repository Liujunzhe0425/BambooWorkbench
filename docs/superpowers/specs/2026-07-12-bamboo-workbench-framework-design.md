# BambooWorkbench（竹简工作台）统一空框架设计规格

日期：2026-07-12  
状态：已完成逐节口头确认，待用户审阅书面规格

## 1. 产品定义

“BambooWorkbench（竹简工作台）”是面向湖南桃花江竹材科技股份有限公司的本地品质数据桌面工具。第一版搭建统一空框架，不实现原竹丝水分、水煮实验和售后三个业务模块的内部算法。

框架提供统一前端、文件选择、任务调度、模块调用、进度展示、人工确认、结果中心、历史记录、AI服务、知识库入口、日志和本地数据管理。三名模块负责人分别实现业务处理，并通过固定协议接入。

第一版成功的核心不是产生真实业务结论，而是证明三个独立模块能够在同一桌面产品中被安装、调用、替换、测试和统一展示。

## 2. 用户、平台和品牌

### 2.1 用户与运行方式

- 第一版为单机单用户；
- 不提供登录、账号或角色权限；
- 用户双击桌面快捷方式直接进入工作台；
- 核心功能可以离线启动和运行；
- 所有配置、任务、知识、日志和成果保存在本地电脑；
- API分析属于可选联网增强，未配置或拒绝联网时不影响本地基础流程。

### 2.2 平台

- 第一版只验收 Windows 10/11；
- 使用 Python 和 PySide6 构建桌面程序；
- 保留跨平台核心边界，后续增加 macOS 打包；
- 不在核心业务层使用只能在 Windows 运行的接口；
- Windows安全凭据、安装程序和系统路径适配封装在平台层。

### 2.3 产品、项目与仓库命名

- 中文产品名：竹简工作台；
- 产品英文名：BambooWorkbench；
- 项目总文件夹名：BambooWorkbench；
- GitHub仓库名：BambooWorkbench；
- 企业专属标识：湖南桃花江竹材科技股份有限公司；
- 团队暂定标准文字：湖大智竹实践团队。

代码、安装包元数据、可执行程序内部标识、默认数据目录和技术文档统一使用`BambooWorkbench`；面向客户的中文界面统一显示“竹简工作台”。不得再使用`Project`、`BambooDesk`或其他临时英文名作为正式项目标识。

## 4. 选定架构

采用“模块化PySide6桌面程序＋独立模块进程＋JSON协议”。不采用进程内插件，也不启动本地Web后端。

```text
PySide6统一界面
→ 应用服务层
→ 任务与模块调度
→ 通过job.json启动独立模块进程
→ 读取进度事件、result.json和成果文件
→ 统一展示、确认、历史与导出
```

选择理由：

- 三名成员的依赖互不影响；
- 单个模块崩溃不导致桌面程序退出；
- 模块可以独立测试、替换和升级；
- 最符合GitHub模块分支与后续交接；
- 后续允许模块使用不同内部实现，只要遵守协议。

### 5.1 职责边界

框架负责：

- 所有PySide6窗口、页面、弹层和用户输入；
- 文件/文件夹选择和任务创建；
- 模块注册、启动、进度、取消和错误；
- 待确认收集和回传；
- 结果中心、历史记录和打开成果文件；
- API设置、联网授权、脱敏预览和密钥保存；
- 知识库管理页面和公共检索接口；
- 本地框架数据、日志和输出索引。

模块负责：

- 判断并读取分配给自己的输入文件；
- 业务字段提取、计算、校验和分析；
- 生成Excel、图表和报告；
- 返回进度、异常、待确认、分析摘要和成果路径；
- 使用确认信息和公共服务响应生成正式结果。

模块禁止：

- 创建PySide窗口或弹窗；
- 直接读取或保存API密钥；
- 修改、移动或删除原始输入文件；
- 直接写框架SQLite数据库；
- 私自修改公共JSON协议；
- 将真实企业数据或密钥提交GitHub。

## 6. 页面和用户流程

### 6.1 左侧导航

- 工作台；
- 任务历史；
- 待确认；
- 知识库；
- 系统设置。

### 6.2 页面

#### 工作台

显示企业名称、三个模块卡片、安装状态、近期任务和待确认数量。真实模块未接入时显示“暂未安装”；开发模式可切换到模拟模块。

#### 模块任务页

三个模块共用页面结构。支持拖拽文件、选择多个文件、选择文件夹、查看文件清单、移除误选文件和创建任务。框架只负责路径和任务，不解析业务内容。

#### 任务执行页

显示总体进度、当前阶段、逐文件状态和日志摘要。允许取消任务。取消时框架先结束模块进程，等待短暂宽限后强制终止，并将未完成成果标记为不可用于正式统计。

#### 待确认中心

显示来源文件、字段、原因、建议值、候选选项、置信度、是否阻塞、是否支持批量应用和是否可以记忆。框架不解释业务含义，只记录和回传用户选择。

#### 结果中心

显示输入数、成功数、跳过数、失败数、异常数量与等级、待确认状态、简要分析、图表预览、来源追溯，以及打开Excel、报告和输出目录的入口。

#### 任务历史

支持按模块、时间和状态筛选。可以重新打开结果、查看确认记录、查看模块版本和重新运行。

#### 知识库

显示公共知识和三个模块知识域，支持导入、启用、停用、版本、来源和模拟检索。空框架不承诺生产级语义检索准确率。

#### 系统设置

包含输出位置、API提供商、API地址、模型、密钥、联网开关、脱敏确认、日志位置、缓存清理和软件版本。

### 6.3 标准流程

```text
选择模块
→ 添加文件或文件夹
→ 确认文件清单
→ 创建草稿任务
→ 查看运行进度
→ 如有待确认则完成确认
→ 框架重新调用模块
→ 查看正式结果
→ 打开或导出成果
→ 任务进入历史记录
```

## 7. 模块协议

### 7.1 模块包

每个模块至少包含：

```text
module.json
run_module.bat
README.md
CHANGELOG.md
requirements.txt或等价依赖清单
src/
rules/
tests/
samples/input/
samples/expected/
docs/
```

### 7.2 必须支持的命令

```text
run_module.bat version
run_module.bat self-check
run_module.bat run --job <job.json路径>
```

### 7.3 任务输入

草稿任务：

```json
{
  "schema_version": "1.0",
  "job_id": "20260712-0001",
  "module_id": "moisture",
  "phase": "draft",
  "input_files": ["D:/.../example.xlsx"],
  "output_dir": "D:/.../tasks/20260712-0001/output",
  "module_config_file": "D:/.../config/moisture.yaml",
  "ai_enabled": false,
  "allowed_knowledge_scopes": ["shared", "moisture"]
}
```

正式处理任务在同一结构中使用：

- `phase: "finalize"`；
- `parent_job_id`；
- `confirmation_file`；
- 可选的`service_response_file`。

### 7.4 进度事件

模块通过标准输出逐行发送JSON：

```json
{"type":"progress","percent":40,"message":"正在处理第4个文件"}
```

非JSON调试文字写入标准错误输出，不能混入进度事件流。

### 7.5 结果

模块在任务输出目录生成`result.json`。合法状态：

- `success`；
- `partial_success`；
- `needs_confirmation`；
- `failed`；
- `cancelled`。

结果至少包含：

- 任务、模块和规则版本；
- 输入、成功、跳过、失败、异常和确认数量；
- 每个文件的状态；
- 异常对象；
- 待确认对象；
- 简要分析；
- 图表预览；
- 成果文件；
- 来源追溯；
- 错误；
- 可选公共服务请求；
- 开始和结束时间。

### 7.6 两阶段确认

```text
模块返回needs_confirmation
→ 框架显示确认问题
→ 用户提交选择
→ 框架写confirmation.json
→ 以phase=finalize重新调用原模块
→ 模块返回正式result.json
```

未完成阻塞性确认的任务不能标记为正式成功。

### 7.7 公共服务请求

模块需要知识或AI时，在草稿结果中返回`service_requests`。框架负责：

- 校验模块是否有权访问知识域；
- 本地检索知识；
- 生成脱敏后的API发送预览；
- 请求用户授权；
- 调用API；
- 将知识结果和AI响应写入`service_response_file`；
- 在finalize阶段回传模块。

模块永远不获得API密钥。

## 8. 本地数据和安全

### 8.1 运行目录

```text
%LOCALAPPDATA%/BambooWorkbench/
├─ config/
├─ data/app.db
├─ modules/
├─ knowledge/
├─ tasks/<job_id>/
├─ logs/
└─ cache/
```

每个任务保存本地输入副本、文件指纹、协议文件、确认记录、结果和输出索引。原文件不被修改。正式任务默认保留；缓存可以清理。

### 8.2 SQLite边界

SQLite只保存框架级数据：任务、状态、模块版本、文件指纹、确认、输出索引、知识元数据、API授权记录和软件设置。模块内部业务表不写入框架数据库。

### 8.3 API安全

- 密钥存入Windows安全凭据；
- 不写入`.env`、普通配置、日志或GitHub；
- 默认不上传原始Excel、客户名称、订单号、联系人和图片；
- 上传前展示脱敏后的结构化摘要；
- 用户逐次或按明确设置授权；
- 拒绝联网后任务继续执行本地部分；
- 所有API调用记录模块、时间、授权和数据类别，不记录密钥。

### 8.4 知识可信度

优先级为：

1. 客户确认的正式规则；
2. 本次人工确认；
3. 历史案例；
4. 大模型通用知识。

历史案例不得自动升级为正式规则。冲突时提示人工复核。

## 9. GitHub协作

### 9.1 仓库

- 位于用户个人GitHub账号；
- 仓库名称固定为`BambooWorkbench`；
- 私有仓库；
- 用户为管理员和最终合并人；
- 三名组员作为协作者；
- 不提交真实企业数据、输出、日志、本地数据库或密钥。

### 9.2 分支

```text
main
integration
module/moisture
module/boiling
module/after-sales
```

- `main`只保存稳定、可演示和可发布版本；
- `integration`用于框架开发、模块接入和整体测试；
- 模块分支在协议冻结后统一从`integration`创建；
- 模块分支主要修改`modules/<module_id>/`、对应测试和文档；
- 公共协议必须通过Issue和框架变更处理。

### 9.3 Pull Request流程

```text
组员自测
→ 同步最新integration
→ 向integration提交PR
→ 自动合同检查与敏感信息扫描
→ 用户验收
→ 修复与回归
→ 合并integration
→ 整体测试
→ integration向main提交PR
→ 发布标签
```

`main`禁止直接推送。发布标签使用语义化版本，例如`v0.1.0`。

### 9.4 自动检查

- 模块目录完整；
- `module.json`合法；
- version、self-check和run命令可运行；
- JSON符合协议；
- 模块测试通过；
- 未修改禁止目录；
- 无真实企业数据；
- 无密钥、`.env`、绝对路径或本地数据库；
- 未破坏其他模块。

- 模拟AI成功；
- 知识无结果；
- 模拟检索成功。

### 10.2 测试层级

- 数据模型和状态机单元测试；
- JSON Schema合同测试；
- 模块进程集成测试；
- SQLite和文件目录测试；
- PySide6关键页面测试；
- 三个模拟模块端到端测试；
- 取消、崩溃和超时故障测试；
- 便携版和安装版干净环境启动测试；
- 敏感信息和Git忽略规则检查。

### 10.3 接入门槛

真实模块必须满足：

- 能在干净环境安装；
- 三条命令可运行；
- 标准样本核心结果符合模块负责人提供的预期；
- 不修改原始文件；
- 重复运行不重复统计；
- 所有结果可追溯；
- 错误和确认结构化返回；
- 无硬编码密钥、账号、真实数据或用户绝对路径；
- 严重问题为零。

## 12. 验收标准

空框架完成必须同时满足：

- 单一桌面入口稳定启动；
- 已确认视觉风格基本还原；
- 三个模块入口和状态正确；
- 三个模拟模块完整跑通任务流程；
- 文件选择、进度、取消、确认、结果和历史可用；
- 模块可以独立替换；
- 模块异常不导致主程序退出；
- 两阶段确认可完成并保留记录；
