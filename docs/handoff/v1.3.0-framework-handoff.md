# BambooWorkbench v1.3.0 框架接入交接

日期：2026-07-26
分支：`agent/v1.3.0-framework`
正式版本：仍为 v1.2.0（本分支未修改中央版本、main、标签或 Release）

## 框架已提供

- 安装根数据布局、实例标记、首次安装清理与更新/卸载保留策略；
- `source/竹丝水分`、`source/水煮模块`、`source/售后分析` 和默认 `output`；
- 任务名称、年份、月份、唯一正式月度槽位和替换候选；
- 不可变月度快照、累计事务和全部受影响月份一次提交；
- `monthly_rollup` manifest、请求、响应、Schema、静态验证与隔离 Runner；
- 成果清单、已知成果根、启动扫描、数据库丢失恢复和完整性标记；
- 历史数据十二月页面、待确认清单、确认草稿和学习开关；
- 模块隔离的偏好证据、精确/逐级回退、撤销与重置界面；
- 默认联网策略、凭据 revision、两类凭据删除和售后已验证配置跳过；
- 缺失成果重新生成、正式任务移除及后续月份重算框架入口。

## 模块负责人接入依据

三个模块统一阅读：

- `docs/contracts/monthly-rollup-v1.3.md`
- `contracts/schemas/monthly-rollup-request.schema.json`
- `contracts/schemas/monthly-rollup-result.schema.json`
- `contracts/schemas/module-manifest.schema.json`
- `contracts/schemas/module-result.schema.json`

框架不会 import 模块内部 Python 类。模块只能通过 launcher、JSON 文件和 manifest 合同接入。

## 能力门控

模块未声明 `capabilities: [monthly_rollup]` 和完整 `monthly_rollup` 对象时，继续走兼容的 v1.2 普通任务流程。声明后，成功 finalize 必须提供有效月度快照；缺少快照或 Schema/路径/哈希不合格会安全失败，不会静默退回非累计成果。

## 联合验收边界

框架复验合同、路径、进程隔离、月份缺口、替换原子性、成果恢复、学习生效条件和联网审计。模块负责人继续对各自 Excel 解释、公式、阈值、统计口径和客户业务成果正确性负责。

组员如发现公共合同不足，应在自己模块的 `docs/framework-change-requests/` 提交独立 FCR；不得直接修改框架目录、integration 或 main。
