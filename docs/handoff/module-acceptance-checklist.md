# 模块接收与安装验收清单

> 每个模块单独复制一份填写。框架通过不等于业务验收通过。

## 基本信息

- 模块：
- 版本：
- 负责人：
- 分支/提交：
- ZIP SHA-256：
- 验收人和日期：

## A. 包完整性

- [ ] `module.json`、入口脚本、README、CHANGELOG、依赖清单齐全
- [ ] `src/`、`tests/`、`samples/`、`docs/` 齐全
- [ ] 规则、模板、脱敏样本、预期结果和示例输出齐全
- [ ] ZIP 解压后没有额外嵌套层级或绝对路径依赖

## B. 合同与运行环境

- [ ] 合同 CLI 返回 0
- [ ] `version`、`self-check` 返回 0
- [ ] 单文件和批量 `run --job` 可无交互执行
- [ ] 进度输出、退出码、`result.json` 和成果路径符合合同
- [ ] draft、人工确认/公共服务、finalize 全流程可运行

## C. 模块负责人拥有的业务正确性证据

- [ ] 核心字段与历史原表逐项核对
- [ ] 公式、阈值、分类和颜色规则均有编号、版本、来源
- [ ] 正常、异常、缺字段、冲突和边界样本有预期结果
- [ ] 核心样本预期结果 100% 通过
- [ ] 经验建议与正式判定规则清楚分离
- [ ] 放行、责任、赔偿、关闭等权限结论保留人工确认

## D. 框架接入与界面

- [ ] 模块卡片名称、版本、状态正确
- [ ] 文件类型和单/批量能力正确
- [ ] 进度、异常、待确认、结果、历史和输出文件正确展示
- [ ] 输出 Excel、图表、报告可以从结果中心打开
- [ ] 拒绝 AI 联网后本地结果仍可完成

## E. 故障隔离

- [ ] 非法 JSON、坏文件、进程崩溃、超时和取消均被结构化处理
- [ ] 模块失败不使桌面程序退出
- [ ] 不留下失控子进程或把半成品登记为正式成功
- [ ] 单文件失败不会无故终止整批

## F. 数据与安全

- [ ] 原文件运行前后哈希一致
- [ ] 不含真实客户数据、日志、数据库、密钥或凭据
- [ ] 不访问框架数据库、凭据、其他模块或未授权目录
- [ ] 所有输出位于任务目录，所有结果可追溯
- [ ] API/知识请求仅通过 `service_requests`

## G. 联合回归

- [ ] 另外两个模拟/真实模块的合同测试仍通过
- [ ] 框架全量测试通过
- [ ] 便携版或安装版中的该模块通过自检和端到端运行

## 结论

- 严重问题：
- 一般问题：
- 已知限制：
- 评审签字：
- 框架接入决定：`接收 / 退回修改 / 有条件接收`
- 客户验收状态：`尚未进行 / 待复验 / 已另行确认`

不得预填“客户已接受”。模块接收只证明技术交接满足要求。
