## 三、必须整改的问题

### MOIS2-01：确认年份后服务 request ID 发生变化

#### 当前问题

draft 产生 `default_year` 确认和 AI 服务请求。框架按 draft request ID 返回合法 `denied` 响应；finalize 应用年份后重新计算候选并生成另一个 request ID，导致原响应被误判为 `SERVICE_RESPONSE_ID_UNKNOWN`、`SERVICE_RESPONSE_ID_MISSING`，最终输出 `service_response_invalid`。

#### 修改要求

1. draft 暴露给框架的服务请求集合和 request ID，必须在本任务 finalize 中保持可验证。
2. 可以选择：确认年份前不创建 AI 请求；或保存并绑定 draft 请求快照；或设计不受该确认变化影响的稳定身份。
3. 不得用 finalize 临时重建的新 ID 否定框架按 draft ID 返回的响应。
4. 用户拒绝 AI 时，本地确定性结果继续生成；不得把拒绝误报为 unknown、missing 或 invalid。
5. 合法 `ok`、`denied`、`error` 响应均必须按实际状态处理。

#### 达标标准

- 月日输入 → 回答年份 → 拒绝 AI → finalize 成功。
- 最终结果不出现 `SERVICE_RESPONSE_ID_UNKNOWN`、`SERVICE_RESPONSE_ID_MISSING` 或 `service_response_invalid`。
- 21/21、166 个样本和 2 个初筛异常的业务基线不退化。
