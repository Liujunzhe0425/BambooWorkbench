# 水煮实验模块 v1.0.1 追加整改与重新交付说明

日期：2026-07-23  
对象：水煮实验模块负责人  
分支：`module/boiling`  
目标版本：仍为 `1.0.1`

## 一、问题

原 PR #38 已合并，其报告、状态语义、AI 脱敏与降级等模块自测均通过。但 AI 请求只有在 `job.ai_enabled=true` 时才会生成，而竹简工作台正式 Draft 固定传入 `false`。

因此真实用户即使导入存在密度/膨胀率等候选的文件，也不会看到 AI 联网授权，DeepSeek/OpenAI Provider 不会被调用。当前测试手工把 `ai_enabled` 改成 `true`，没有覆盖正式框架入口。

## 二、整改目标

不修改框架、不增加 API Key 读取、不直接联网，只调整水煮模块的统一服务请求触发条件：

1. Draft 始终先执行确定性解析、公式计算和规则筛查。
2. 确有适合 AI 辅助解释的候选时，直接生成统一 `service_requests`，不得依赖框架传入 `ai_enabled=true`。
3. 没有候选时保持 `service_requests=[]`，不制造无意义授权。
4. Finalize 仍只从 `service_response_file` 读取框架响应。
5. AI 仍只进入“AI 辅助建议”，不得修改公式、阈值、确定性数值、等级、业务状态或人工确认。
6. 拒绝、无密钥、错误、超时、非法 JSON、证据不匹配时继续输出完整离线成果。

## 三、必须新增的真实框架回归

不得只调用模块内部 `run_job` 并手工构造 `ai_enabled=true`。至少增加使用仓库真实 `TaskService.create_and_start(ModuleId.BOILING, ...)` 的测试：

- 有候选文件：Draft 产生 `service-consent:<request_id>`，允许后进入 Finalize 并清空 `service_requests`；
- 拒绝：任务仍成功并明确标注离线降级；
- 无候选文件：不出现 AI 授权；
- 两种情况下确定性 JSON 业务记录保持不变。

可使用现有脱敏夹具 `02_density_observation.xlsx` 验证有候选场景。

## 四、重新交付

1. 同步最新 `origin/integration` 到 `module/boiling`。
2. 只修改 `modules/boiling/`，不得修改框架或其他模块。
3. 保持版本 `1.0.1`，更新 `CHANGELOG.md` 和测试证据。
4. 由于原 PR #38 已合并，请创建新的 Draft PR：`module/boiling → integration`。
5. 不得指向 `main`，不得自行合并。
6. 通知框架负责人 PR 号、提交号、模块全套测试结果和真实 TaskService 三场景结果。

## 五、通过标准

- 现有 45 项模块测试继续通过；
- 新增真实框架测试通过；
- version、self-check、Ruff 和合同通过；
- 实际竹简工作台可展示水煮 AI 授权；
- AI 不改变任何确定性业务输出；
- 无候选或 AI 不可用时仍能正常生成 Excel、Markdown 和 JSON。
