# 竹丝水分检测模块 v1.0.1 框架适配审核与最终补交要求

日期：2026-07-23  
适用 PR：#41（`module/moisture` → `integration`）  
当前结论：框架适配已完成；模块仍需最小补交，PR 暂不应合并。

## 一、已确认采用的产品方案

1. 日常竹丝水分汇总保持完全确定性，不自动联网，不由 AI 修改业务表格、颜色或结论。
2. 日常汇总删除“模型分析记录”工作表，取消 AI 对红色/蓝色标识的升级。
3. AI 作为用户主动打开的独立辅助报告：选择一个当前汇总，可选历史汇总和已批准经验，再填写分析问题。
4. 框架先展示脱敏预览；用户逐次选择“允许”后才调用已配置的 AI 服务。
5. 拒绝联网、配置错误、超时或无效响应必须结构化降级，不得伪造 AI 报告。
6. 模块业务规则、确定性计算和人工复核结论始终高于模型通用知识。

## 二、框架已经完成的内容

- 新增独立“竹丝水分 · AI 汇总报告”页面，普通任务页面与 AI 报告入口分离。
- 新增任务私有 `module-config.json`，不会写入 API Key；draft/finalize 两阶段保持同一配置。
- 新增历史汇总与已批准经验管理请求/响应合同，以及模块私有持久化目录。
- 新增 `module.json` 的 `capabilities` 和 `management_entrypoint` 可选字段；未声明能力时不显示入口。
- 新增 AI 服务错误/超时安全降级与结果页中文提示。
- 新增受控 `manage --request --response` 进程命令、路径约束、超时/取消和响应身份校验。

## 三、模块负责人必须补齐的内容

### 1. 更新模块清单

`modules/moisture/module.json` 至少更新：

```json
{
  "module_version": "1.0.1",
  "management_entrypoint": "run_management.bat",
  "capabilities": ["ai_report"]
}
```

保留其余现有字段。`run_management.bat` 必须真实存在，并支持：

```powershell
run_management.bat manage --request <绝对请求路径> --response <绝对响应路径>
```

### 2. 实现窄化的资料管理入口

入口只需实现四项合同操作：

- `list_history_summaries`
- `import_history_summary`
- `retire_history_summary`
- `list_approved_experiences`

请求与响应严格使用仓库 `contracts/schemas/module-management-*.schema.json`。不得输出绝对路径、堆栈、原始客户敏感数据或密钥到 `display_name`、`title`、`message`。

### 3. 补齐五表历史兼容

当前 PR 明确拒绝 v1.0.0 的五工作表历史汇总（含“模型分析记录”），不符合客户从 v1.0.0 升级后继续引用既有历史数据的要求。必须做到：

- v1.0.1 四表汇总可导入；
- v1.0.0 五表汇总也可导入；
- 对五表格式忽略旧“模型分析记录”内容，只读取确定性业务工作表；
- 仍校验核心字段、文件完整性和 SHA-256；
- 非四表/五表的未知结构继续明确拒绝。

### 4. 完成客户可见文本与版本

- `module_version`、`CHANGELOG.md`、交付报告统一为 `1.0.1`。
- AI 报告输出标签、`analysis_summary` 和可读报告标题使用清晰中文。
- 普通分析报告的可读性仍由水分模块负责，不把大量内部 warning/规则调试字段直接作为客户正文。

## 四、模块方重新交付与自测要求

1. 先同步最新 `integration`，解决合同镜像并运行模块 schema 同步工具。
2. 只在原 PR #41 对应 `module/moisture` 分支继续提交，不新建重复 PR，不直接合并。
3. 至少提交以下证据：
   - 模块全部测试通过；
   - `version`、`self-check` 通过；
   - 普通确定性汇总不产生 AI 请求；
   - 当前汇总独立 AI 报告 draft → 授权/拒绝 → finalize 通过；
   - v1.0.0 五表与 v1.0.1 四表历史均可导入并参与报告；
   - provider error/timeout/invalid 时只生成降级记录，不生成虚假 Markdown 报告；
   - 便携运行环境闭环通过。
4. 将 PR 从 Draft 改为 Ready for review，并通知框架负责人复验；不得自行合并到 `integration` 或 `main`。

## 五、责任边界

- 框架负责人验收：合同、进程、路径、UI 入口、AI 授权、降级、安装兼容和模块接入。
- 水分模块负责人验收：Excel 计算/格式、历史数据解释、业务规则、AI 提示与报告内容正确性。
- 本轮框架不会修改水分业务算法；合同镜像的同步属于框架公共合同升级，不代表接管模块业务责任。
