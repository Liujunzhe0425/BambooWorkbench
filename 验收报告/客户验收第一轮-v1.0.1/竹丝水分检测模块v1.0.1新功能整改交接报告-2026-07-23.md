业务分支：`module/moisture`

## 一、交接结论

经重新评估，原整改说明要求在普通 `analysis_report.md` 中同时呈现确定性统计、
AI 辅助复核和技术追溯。这会继续把“数据汇总”和“AI 分析”混在一次任务中，
客户也无法主动决定分析范围。

v1.0.1 现决定采用新功能拆分解决该问题：

1. **普通汇总生产**只负责 Excel 解析、公式复核、Decimal 统计、规则初筛、
   确定性 Markdown 和四工作表 XLSX；
2. 普通汇总不再自动请求 AI，不再生成“模型分析记录”，不再由 AI 将橙绿升级为红蓝；
3. **AI 汇总报告**改为独立入口，由客户主动选择当前汇总表、历史资料、
   approved 经验并输入问题；
4. AI 结果单独生成 `ai_analysis_report.md` 和 `ai_analysis_result.json`，
   不修改汇总表、确定性数值、规则命中或颜色。

该方案已经完成模块侧、主框架适配前的 C0—C3 开发，但尚未完成框架页面、
真实 Provider 闭环和 v1.0.1 最终交付门禁。因此当前状态是：

> 模块内核已具备，客户 GUI 尚不可直接使用；需要框架负责人批准并实施当前 FCR。

| 正常批次逐条堆积、客户阅读困难 | 普通报告只保留确定性概况；深入分析由独立 AI 报告按问题生成 | 已部分解决，仍需负责人确认普通报告表达是否可接受 |

## 三、客户实际使用流程

### 3.1 普通汇总

```text
选择原始检测 Excel
→ 模块确定性解析、公式复核和统计
→ 规则初筛与日期排序
→ 输出四工作表 moisture_summary.xlsx
→ 输出确定性 analysis_report.md 和 result.json
```

新汇总文件固定包含：

1. 竹丝含水率统计；
2. 异常分析明细；
3. 趋势分析；
4. 来源追溯。

“模型分析记录”已经取消。普通汇总不自动联网，也不自动调用 AI。

### 3.2 独立 AI 汇总报告

```text
客户主动进入“AI汇总报告”
→ 选择当前汇总表
→ 选择历史资料（可选）
→ 选择 approved 经验（可选）
→ 输入希望分析的问题
→ 模块生成脱敏、限长预览
→ 客户逐次同意联网
→ 主框架调用 Provider
→ 模块严格校验响应
→ 输出独立 AI Markdown 和 JSON
```

AI 报告可用于总体情况、历史比较、需复核批次、可能原因和后续建议，但只属于
辅助分析，不形成正式不合格、责任、处罚、放行或处置结论。

## 四、模块侧已完成内容

### 4.1 普通汇总去 AI 化

- 移除普通 draft 的 AI review request；
- 移除普通 finalize 的 AI response 应用和降级逻辑；
- 停止红蓝提升，新产物只保留确定性橙、绿或无色；
- 删除“模型分析记录”工作表；
- 保留人工 confirmations；
- Knowledge 引用即使不可用也不得改变确定性结果。

### 4.2 独立 AI 报告私有合同

已增加严格、版本化的模块私有合同：

- `summary` 与 `ai_report` 操作配置；
- 历史资料索引；
- approved 经验目录；
- AI analysis request；
- AI analysis response；
- AI analysis result。

配置只保存输入索引和稳定 ID，不保存 API Key、Provider 配置、绝对路径或完整经验正文。
中央合同没有修改。

### 4.3 历史资料和经验选择

- 历史资料采用本地只读副本和 JSON 索引；
- 相同 SHA-256 不重复导入；
- 支持 active/retired 状态；
- 索引写入使用临时文件、flush、fsync 和 `os.replace`；
- 拒绝路径越界、symlink、junction 和 reparse point；
- 经验只允许选择当前有效的 approved 版本；
- 经验选择必须同时匹配 ID、版本和 SHA-256；
- draft、retired、过期或哈希不一致的经验不得进入 AI 上下文。

### 4.4 AI 请求、响应和产物

- 每个 AI 报告任务最多声明一个请求；
- `requires_user_consent=true`；
- request ID 基于 root job ID 和确定性上下文哈希；
- payload 不超过 65,536 UTF-8 字节；
- 供应商默认使用稳定匿名标识；
- 不发送完整 Excel、原始行、绝对路径或文件修改时间；
- 记录历史、经验和复核项的总数、发送数及省略数；
- 严格校验 request ID、Schema、context hash、批次和 evidence；
- 拒绝重复 JSON 键、未知证据和禁止的正式质量结论；
- 合法响应生成 `ai_analysis_report.md` 和 `ai_analysis_result.json`；
- denied、error、timeout、缺失或非法响应安全降级，不伪造 AI 分析；
- finalize 后 confirmations 和 service_requests 为空；
- 当前汇总表读取前后校验 SHA-256，AI 分析不得修改原文件。

## 七、负责人需要确认的事项

### 7.1 产品决策

- 是否正式批准以“普通确定性汇总＋独立 AI 报告”取代原来的普通报告内嵌 AI 复判；
- 是否接受新版本不再生成“模型分析记录”工作表；

- 是否仍要求单独重写普通 `analysis_report.md` 的客户表达。如果仍要求，该工作需要另列模块任务，
  不能把独立 AI 报告误当成已经完全满足原说明第二节。

### 7.2 框架决策

- 审核 FCR，并填写审核结论、实施分支/PR、可复用接口和前置要求；
- 冻结 moisture 模块数据目录和管理进程调用方式；

- 确认现有脱敏预览、逐次同意、Provider 和 service response 能用于独立任务；
- 确认结果中心能够展示 Markdown/JSON 和公开降级原因。

### 7.3 业务与数据决策
