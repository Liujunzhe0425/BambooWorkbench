## 二、当前重复项诊断

在 41 份历史数据的草稿结果中，现有 8 项确认分别为：

- 1 项批次 `product_usage`；
- 4 项不同文件的密度结论冲突；
- 3 项不同文件/试件/单元格的膨胀率数值冲突。

现有证据显示它们是不同来源共享相同 `field`，不是同一条记录被重复插入。框架会显示中文含义、`1/N` 序号、原因、文件、工作表和单元格。

模块负责人仍需独立确认这些冲突的业务识别是否正确，框架方不判断密度或膨胀率计算结果是否正确。

## 三、模块负责人必须补充的验证

### 1. 确认项唯一性与去重

为确认项增加自动测试，至少断言：

- `confirmation_id` 全局唯一且重复运行保持稳定；
- 同一 `source_file + sheet + cell_or_range + field + reason` 不会重复出现；
- 不同文件、不同试件或不同单元格允许分别确认；
- `reason` 必须写明试件或结论冲突类型；
- `source` 必须保留文件、工作表和适用的单元格；
- 批次用途只生成一次，不为每个缺失文件重复生成；
- finalize 后已经回答的确认项不再重复出现。

### 2. 确认 `product_usage` 业务选项

模块当前返回“地板、家具、墙板、栏杆、其他”。负责人必须确认：

- 选项是否覆盖客户真实用途；
- 每个用途对应的膨胀率标准是否有已确认来源；
- “其他”如何进入人工复核；
- 批量应用的适用范围；
- 不同文件用途不一致时不会误用同一答案。

这些属于水煮模块业务正确性，由模块负责人负责。

### 3. 报告和结构化记录合同

框架已经提供 `.md` 和 `.json` 内置查看器。模块负责人仍需保证：

- `boiling_analysis.md` 和 `boiling_records.json` 实际存在；
- `outputs[].path` 指向真实普通文件；
- MIME 分别为 `text/markdown` 和 `application/json`；
- JSON 为有效 UTF-8，可被标准解析器读取；
- 报告和记录中的业务内容由负责人确认正确。

## 四、如需框架进一步适配

如果模块还需要新页面、按钮、专用确认控件或合同字段，必须提交：


使用 `docs/handoff/templates/框架适配请求模板.md`。不要直接修改框架目录。

## 五、重新交付要求

1. 合并最新 `origin/integration` 到 `module/boiling`；
2. 只修改 `modules/boiling/`；
3. 更新模块版本、`CHANGELOG.md`、测试和说明；
4. 由负责人完成公式、规则、确认项和输出正确性自测；
5. 推送 `module/boiling`；
6. 创建 `module/boiling → integration` PR，不得指向 `main`，不得自行合并；
7. 通知项目负责人提交号、模块版本、PR、业务自测结论、确认项统计和回滚版本。

## 六、通过标准

- 模块负责人确认不存在相同来源/字段/原因的真重复；
- 不同确认项具有稳定 ID、明确原因和完整来源；
- `product_usage` 选项及批量应用口径由负责人确认；
- Markdown、JSON、Excel 输出合同保持合法；
- 模块业务测试由负责人确认通过；
- 框架兼容、无 Python 运行时和回归测试通过；
- PR 不越过 `modules/boiling/`。

框架方不会重新计算密度、膨胀率或评价业务结论。
