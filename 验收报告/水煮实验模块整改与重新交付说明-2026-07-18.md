# 水煮实验模块整改与重新交付说明

> 发送对象：水煮实验模块负责人  
> 当前分支：`module/boiling`  
> 当前 PR：#14（`module/boiling` → `integration`，保持 Draft）  
> 整改范围：只允许修改 `modules/boiling/`

## 一、整改目标

让水煮模块能够直接通过竹简工作台正式框架处理 41 份企业历史 Excel，正确提取试件、复核公式和规则、保留原表结论、生成合法的 `result.json`、Excel、图表和分析报告，并通过模块测试、全仓门禁和真实框架端到端验收。

完成标准不是“自造样例能运行”，而是：

- 41 份历史表均有明确、可追溯的单文件结果；
- 完整表的密度、密度差、膨胀率与独立复核一致；
- 未完成表只影响自身；
- 所有状态符合框架合同；
- 模块负责人不修改框架代码来掩盖模块问题。

## 二、必须整改的问题

### BOIL-01：兼容真实试件结构

解析器必须兼容至少以下真实标签：

- `端1-1`、`端1-2`、`中1`、`端2-1`、`端2-2`；
- 纯数字 `1`、`2`、`3`、`4`；
- 复测表中的实际标签；
- 4 个、5 个及复测试件布局；
- A:H、A:I、A:J 等不同实际使用范围。

不得依靠固定文件名或固定 5 个试件；应根据表头、测量块和平均值行识别。41 份历史表应识别出约 193 个试件；若最终数量不同，必须逐文件说明原因并提供对照证据。

### BOIL-02：重新定义阻断字段

只把影响核心计算的字段设为阻断项。压制日期、班长、浸胶日期、订单号为 `/` 或空时：

- 保留原值或空值；
- 在缺失字段/提醒中记录；
- 不得阻止已有试件数据进入密度和膨胀率统计。

真正没有测量数据、没有可计算试件或工作簿未完成时，才进入“信息不足”。

### BOIL-03：实现正式密度规则

规则至少包括：

1. 每个有效试件密度位于 `1.1～1.3 g/cm³`，边界包含；
2. 任意两块有效试件的密度差 `≤0.1 g/cm³`；
3. 同时输出最小值、最大值、密度差、规则命中和来源单元格；
4. 原表结论与复核结果不一致时同时保留，生成可执行的人工确认项。

注意历史表存在边界取整和人工判断差异。不得为了强行匹配原表而删除规则；应记录原始精度、显示精度、复核精度和冲突。

### BOIL-04：按历史标准重建膨胀率/等级规则

删除当前地板 8%、家具 7%、墙板 9%、栏杆 8% 的暂存阈值。规则文件必须表达：

- 绿色优等：2h 膨胀率 `≤6.5%`，同时受开裂观察约束；
- 地板/家具：`>6.5% 且 ≤8%` 为蓝色合格，`>8%` 为红色不合格；
- 墙板/栏杆：按客户确认后的完整区间执行，`>12%` 为红色不合格；
- 产品用途缺失时不得猜测，可生成一个支持批量应用的确认项；
- 开裂程度未在结构化数据中提供时，不得凭空推断，应保留原表结论并明确人工观察边界。

**已确认口径（2026-07-18）：墙板/栏杆 `>6.5% 且 <8%` 在 v0.1 必须进入人工复核，不自动判为绿色、蓝色或红色；待客户补充正式标准后再通过新规则版本固化。**

### BOIL-05：修复结果状态合同

- `needs_confirmation` 必须至少有一个合法 confirmation；
- 只有异常但不需要人回答时，应使用合同允许且语义正确的状态，不得制造空确认；
- 每份输入必须有一条 `file_results`；
- `processed_count + failed_count + skipped_count` 与输入处理事实一致；
- `result.json` 必须通过框架 `ModuleResult` 校验。

### BOIL-06：修复输出内容

Excel 至少包含：正常汇总、未纳入统计、试件明细、规则说明和图表。必须做到：

- 有效历史表不再全部落入“未纳入正常统计”；
- 异常颜色、文字状态和规则 ID 一致；
- 密度范围、密度差、膨胀率、用途、原表结论、自动复核结论和冲突均可追溯；
- Markdown 报告不得把正式历史标准写成“脱敏暂存值”。

### BOIL-07：整理测试资产

- Excel 脱敏夹具只能保留在 `modules/boiling/tests/fixtures/`；
- 删除 `modules/boiling/samples/input/*.xlsx`、`samples/actual/**/*.xlsx`、`docs/evidence/*.xlsx` 等重复或违规副本；
- JSON 预期可保留在 `samples/expected/`，但路径必须与测试一致；
- 禁止提交 `__pycache__`、`.pyc`、真实企业表、绝对客户路径和运行产物。

### BOIL-08：补齐不可回避的自动测试

至少新增并通过：

1. 真实脱敏模板的 4 试件、5 试件、端/中标签和纯数字标签；
2. 密度单块越界、密度差超 0.1、边界等于 1.1/1.3/0.1；
3. 地板/家具 6.5%、8% 及边界两侧；
4. 墙板/栏杆 12% 边界，以及 `>6.5% 且 <8%` 必须进入人工复核；
5. 原表结论与复核冲突；
6. 产品用途一次确认后批量应用；
7. 未完成表与正常表同批运行；
8. `result.json` 模型校验；
9. 41 份历史表的脱敏结构回归；
10. 原文件 SHA-256 不变。

不得通过删除断言、改低预期或把异常样本改成正常样本来让测试变绿。

### BOIL-09：代码质量

修复 Ruff 行长、导入和格式问题，确保新的主仓门禁能够扫描 `modules/boiling` 并执行其测试。

## 三、验收通过标准

- 41 份历史表不再出现“有效处理 0”；
- 真实完整表的关键公式和规则结果与独立复核一致；
- 合法 `result.json`、Excel、图表、Markdown 均生成；
- 原始文件哈希不变；
- 全仓 `scripts/verify_repo.ps1` 通过；

## 四、重新交付操作（不要新建 PR）

在自己电脑执行：

```powershell
git switch module/boiling
git fetch origin
git merge origin/integration
```

只修改 `modules/boiling/`，完成后执行：

```powershell
.\.venv\Scripts\python.exe -m app.tools.module_contract_cli validate modules/boiling
modules\boiling\run_module.bat version
modules\boiling\run_module.bat self-check
.\.venv\Scripts\python.exe -m pytest modules/boiling/tests -q
$env:BAMBOO_PYTHON=(Resolve-Path '.\.venv\Scripts\python.exe').Path
powershell -ExecutionPolicy Bypass -File scripts/verify_repo.ps1
git diff --check
git status --short
```

提交并推送到原分支：

```powershell
git add modules/boiling
git commit -m "fix(boiling): pass historical-data integration acceptance"
git push origin module/boiling
```

交付规则：

- 更新现有 PR #14，不要新建 PR；
- PR 目标保持 `integration`；
- 保持 Draft；
- 不要合并 PR；
- 不要向 `main` 或 `integration` 直接 push；
- 不要修改 `app/`、`core/`、`ui/`、`contracts/`、`.github/`、`scripts/` 或其他模块。

推送后在 PR 留言：提交号、模块测试结果、全仓门禁结果、41 份历史表统计、墙板/栏杆空档区间人工复核测试结果，等待框架负责人复验。
