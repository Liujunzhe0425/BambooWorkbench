## 三、必须整改的问题

### BOIL3-01：缺少安装版独立运行时

#### 当前问题

当前模块没有 `modules/boiling/build_portable_runtime.ps1`，便携包内也没有水煮冻结程序。客户电脑没有 Python 时无法执行真实业务模块。

#### 修改要求

1. 新增可重复执行的 `modules/boiling/build_portable_runtime.ps1`。
2. 将独立运行时安装到 `dist/BambooWorkbench/modules/boiling/` 内；不得把冻结产物提交到 Git。
3. 入口 BAT 必须优先自动使用便携目录内的本模块运行时，同时保留源码开发模式。
4. 冻结入口必须正确定位模块根目录和 `rules/default_rules.yaml`，不能依赖开发机目录。
5. 构建脚本只允许清理仓库构建目录和便携包内本模块运行时目录。

### BOIL3-02：无 Python 时错误返回成功退出码

#### 当前问题

在隔离环境执行便携 BAT 的 `version`，标准错误输出：

```text
{"type":"error","message":"Python 3.12 was not found"}
```

但进程退出码为 `0`。这会让框架或 CI 把“环境缺失”误判为成功。

#### 修改要求

1. 缺少运行时或依赖时必须稳定返回退出码 `4`。
2. `version` 成功时标准输出必须包含模块版本，标准错误为空。
3. `self-check` 成功时返回 0；失败时不得吞掉子进程退出码。
4. 为 BAT 的无 Python、运行时成功、运行时失败三种路径增加进程级测试。

#### 达标标准

- 无 Python、无模块运行时时返回 4，不再伪成功。
- 正式便携包中不依赖 Python，`version`、`self-check` 均返回 0。
- 一个脱敏样本通过便携 BAT 完成 draft/finalize，产生合法 Excel、Markdown、业务 JSON 和 `result.json`。
- `scripts/build_portable.ps1` 自动完成构建和隔离环境验证。
- 现有 `31 passed` 和 41 份历史数据基线不退化。
