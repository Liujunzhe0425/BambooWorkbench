# DeepSeek 结构化建议快速响应适配请求

## 1. 业务目标和使用场景

水煮模块在完成确定性解析和规则筛查后，会把少量脱敏候选提交给工作台统一 AI 服务，用于补充面向人工的原因分析、核对项和复测建议。AI 结果不参与公式、阈值、等级、业务状态或人工确认判定。

模块已将单次请求收紧为最高优先级的 1 个候选和 12 KiB 负载上限，但 DeepSeek V4 在框架固定的 30 秒响应窗口内仍可能超时。希望框架为结构化辅助建议提供可复验的快速响应设置。

## 2. 现有接口不能满足的原因

- `core/ai/providers.py` 当前使用固定 30 秒 HTTP 超时，模块无法通过统一服务合同调整。
- DeepSeek V4 默认开启思考模式；当前统一提供方请求只包含模型、消息和响应格式，模块无法请求关闭思考模式。
- 实测 41 个脱敏输入文件共识别 33 个候选，模块收紧为 6 个、约 11.8 KiB 后仍发生 `ReadTimeout`；继续收紧为 1 个只能降低概率，不能解决提供方思考耗时超过固定窗口的问题。
- 对 `https://api.deepseek.com` 的未授权连通测试约 0.19 秒即返回 401，说明该次问题不是基础地址无法建立连接；历史日志同时出现过 `ConnectError` 和 `ReadTimeout`，两者需要分别呈现。

## 3. 希望框架增加的能力

必须：

1. DeepSeek 结构化 JSON 辅助请求默认发送 `thinking: {"type": "disabled"}`，或由框架提供等效的、受控的逐请求/逐提供方思考模式设置。
2. 提供安全边界内的响应超时配置，建议允许 30～120 秒、默认 60 秒；设置由框架保存和应用，模块不得读取密钥或直接调用提供方。
3. 保持现有用户授权、脱敏预览、密钥管理、审计和离线降级流程不变。
4. 保持 `timeout`、`error`、拒绝、无密钥等现有服务状态语义，并让界面能够区分连接失败与读取超时。

可选：

- 对连接失败或读取超时允许最多一次框架级重试；不得重复要求授权，也不得产生重复业务记录。

## 4. 输入、输出、状态和失败处理

- 输入：现有统一 AI `service_request`，无需模块新增厂商密钥或网络参数。
- 输出：现有统一 `service_response_file`，响应正文仍必须是模块声明的严格 JSON。
- 状态：成功时维持 `completed`；超时、连接失败、拒绝、无密钥、限流和提供方错误沿用现有状态。
- 失败处理：框架写入明确失败状态，模块读取后生成完整离线成果；不得因 AI 失败改变确定性业务输出。

## 5. 合同和兼容性

优先在框架提供方实现中处理，不修改公共模块合同。若必须增加设置，应为可选框架配置并提供兼容默认值，旧模块和旧任务无需修改即可继续运行。

本请求不要求修改水煮模块的任务 JSON、结果 JSON、公式、阈值、等级或人工确认边界。

## 6. 数据安全和人工确认边界

- API Key 继续仅由框架管理；水煮模块不得读取、保存或直接使用。
- AI 调用继续经过用户逐次授权和脱敏预览。
- AI 只生成辅助文字，不能修改确定性数值、规则命中、等级、业务状态或人工结论。
- 超时设置和重试不得绕过授权，不得扩大提交给提供方的数据范围。

## 7. 可操作、可复验的验收标准

1. 使用记录或模拟传输验证：DeepSeek 结构化请求包含关闭思考模式的参数，且请求正文不包含 API Key。
2. 设置 60 秒超时后，模拟在 30～60 秒内返回的合法 JSON 能成功完成；超过设置上限时稳定返回 `timeout`。
3. 模拟连接失败时返回与读取超时不同的可识别错误类别，模块仍能 finalize 并生成离线成果。
4. 使用水煮模块 v1.3.0 的脱敏 41 文件任务验证：33 个候选中只提交最高优先级 1 个，用户允许后可获得合法结构化建议并完成 finalize。
5. 用户拒绝、无密钥、超时和非法 JSON 四种场景都能生成完整离线成果，且 AI 前后确定性业务 JSON 一致。
6. 其他模块不配置新选项时行为兼容，现有合同测试和真实完整任务流测试通过。

## 8. 模块方已完成和等待框架提供

模块方已完成：

- 候选稳定排序、脱敏、证据约束和严格响应校验。
- 单次请求收紧为最高优先级 1 个候选、12 KiB 负载上限和精简响应结构。
- 拒绝、无密钥、断网、超时、错误、非法 JSON 和证据不匹配时的完整离线降级。
- AI 前后确定性业务输出不变的模块测试。

等待框架提供：

- DeepSeek 结构化请求的关闭思考模式能力。
- 有安全边界的提供方响应超时配置。
- 连接失败与读取超时的明确状态展示；框架认为安全时可增加一次受控重试。
