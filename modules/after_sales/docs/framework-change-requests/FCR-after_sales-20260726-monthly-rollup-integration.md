# 框架适配请求：接入售后月度快照、离线累计与学习描述

## 1. 业务目标与使用场景

售后负责人每月完成 Excel 分析以及“售后费用、责任工厂、投诉类型”人工确认后，需要形成该月份不可变的正式快照。用户打开同年任意正式月份时，看到的不是单月孤立数据，而是截至该月已有正式月份的累计台账、Excel、Word 报告、图表和年度看板。

当用户替换早期月份时，框架需要用新快照替换旧快照，并重新生成该月及所有已有后续月份成果。累计重算必须完全离线，只能复用最终人工值。投诉类型等适合学习的枚举确认项需要向框架提供稳定、脱敏的学习描述。

## 2. 当前限制

1. 当前公共 `job.json` 只支持 `draft/finalize`，没有任务目标年份、目标月份和正式月份身份。
2. 当前公共结果合同没有“内部月度快照”工件、快照 Schema 路径或“不在结果中心展示”的标记。
3. 当前框架没有向模块传递有序正式快照、SHA-256、授权暂存目录和强制离线标志的累计调用流程。
4. 当前 `ConfirmationPrompt` 公共合同没有可选、版本化 `learning` 字段，模块不能把学习描述直接放入 `result.json`，否则会破坏现有 Schema。
5. 当前任务存储没有同模块、同年份、同月份正式槽位、替换候选、后续月份重算和原子提交事务。
6. 当前历史数据页面没有按年份、模块和十二个月展示正式快照与替换状态的入口。

模块 v1.3.0 已在模块目录内实现：

- `rollup --request <absolute-json> --response <absolute-json>` 离线累计入口；
- `schemas/monthly-snapshot.schema.json`；
- `schemas/monthly-rollup-request.schema.json`；
- `schemas/monthly-rollup-response.schema.json`；
- finalize 成功且本批记录均完成三项人工复核、年月有效时生成模块内部快照；
- `after_sales_learning_descriptors.json` 模块内部学习描述旁路文件。

这些能力无法替代框架的正式槽位、事务、知识库和页面编排。

## 3. 请求的框架改动

### 3.1 页面与交互

- 页面/区域：任务创建页增加目标年份、目标月份和任务名称；新增“历史数据”页面。
- 按钮/控件：同年份和售后模块下显示十二个月卡片；已有月份支持“替换本月”，并在操作前展示受影响的后续月份。
- 用户操作顺序：选择年月并创建任务 → draft → 人工确认 → finalize → 校验快照 → 累计渲染 → 原子发布。
- 输入与校验：年份和月份必填；同月份已有正式结果时必须进入替换候选流程，不得直接覆盖。
- 加载、空状态、错误状态：区分未创建、候选、重算中、失败可重试和正式结果；累计失败不得切换正式结果。
- 结果展示：内部快照和学习描述不作为普通用户成果按钮展示；正式月份结果页展示累计成果。

### 3.2 接口与合同

期望框架按已批准设计文档第 9、10、13、14 节发布精确公共 Schema，并完成以下适配：

1. manifest 识别 `capabilities: ["monthly_rollup"]`。
2. finalize 结果允许登记一个内部月度快照，公共信封由框架校验，`payload` 使用模块自有 Schema 校验。
3. 框架生成模块自有累计请求，字段至少包含：

```json
{
  "schema_version": "1.0",
  "request_id": "framework-generated-id",
  "module_id": "after_sales",
  "module_version": "1.3.0",
  "year": 2026,
  "target_month": 6,
  "offline_required": true,
  "snapshots": [
    {
      "month": 1,
      "path": "框架授权的绝对快照路径",
      "sha256": "64位小写SHA-256"
    },
    {
      "month": 3,
      "path": "框架授权的绝对快照路径",
      "sha256": "64位小写SHA-256"
    }
  ],
  "staging_output_dir": "框架授权的绝对暂存目录",
  "rule_snapshot_id": "规则快照身份",
  "experience_snapshot_id": "经验快照身份",
  "business_config_snapshot_id": "业务配置快照身份"
}
```

4. 框架通过模块入口调用：

```text
run_module.bat rollup --request <absolute-request-json> --response <absolute-response-json>
```

5. 响应成功时校验年月、使用月份、快照哈希、工件路径包含性和工件 SHA-256；失败时读取稳定错误码，不向用户显示 traceback 或临时路径。
6. 公共 `ConfirmationPrompt` 增加可选 `learning` 描述，字段采用设计文档第 13 节批准结构。未提供时保持旧模块兼容。
7. 在精确公共 Schema 发布前，框架不要根据模块内部旁路文件自行推断新公共字段。

旧模块兼容方式：没有 `monthly_rollup` capability 的模块继续走现有 draft/finalize，不调用累计入口；没有 `learning` 的确认项继续按现有方式处理。

### 3.3 公共服务、存储或打包

- 所需能力：正式月份索引、候选快照、SHA-256 校验、同年累计请求、后续月份重算事务、学习证据生效/撤销、历史数据页面。
- 调用时机：finalize 成功并取得候选快照之后、正式月份切换之前。
- 数据保存位置：框架受控任务输出根和数据库；模块不选择正式存储位置。
- 安装版/便携版要求：携带模块新增 Schema 和 `rollup` 命令；运行时不依赖系统 Python 或开发者 `.venv`。
- 无服务或失败时：保留候选和诊断，正式月份及后续成果不变，学习证据不生效。

## 4. 责任边界

- 模块方已经完成：最终人工值快照、快照/请求/响应模块 Schema、离线累计渲染、完整累计成果、哈希/年月/顺序/路径校验、稳定错误码、投诉类型学习描述、缺月/替换/跨年/乱序/损坏/零网络测试。
- 等待框架提供：任务年月、内部快照登记、正式槽位、替换事务、后续月份批量重算、公共 learning 合同、知识库写入和历史数据页面。
- 仍由模块方负责的业务逻辑：售后费用口径、责任工厂、投诉类型、累计台账、Excel、Word、品牌/原因/费用图表及年度看板正确性。
- 需要人工确认的结论：售后费用、责任工厂、投诉类型；人工最终值永远优先于规则、学习和 AI 建议。

## 5. 数据、安全与权限

- 模块保持 `requires_network:false`，累计入口不导入 AI 适配代码，不读取 API Key、Windows 凭据或环境变量，不访问 Provider。
- 快照不保存客户原文、客户身份、原始单元格或绝对输入路径；来源文件使用脱敏序号。
- 学习上下文只包含稳定枚举：品牌分组和产品分组；不包含自由文本、客户身份、路径或原始单元格。
- 快照和输出使用 SHA-256 完整性校验；SHA-256 不用于身份认证。
- 模块拒绝符号链接、junction、非普通文件、哈希不符、其他模块/年份、重复月、乱序和越界月。
- 框架必须继续负责暂存目录授权、路径包含性、同卷原子发布、跨卷复制校验和正式结果事务。

## 6. 兼容性与迁移

- 是否破坏现有合同：否。普通 `run --job` 的现有公共结果保持不变；新能力通过 capability 和独立命令增加。
- 是否兼容当前正式版模块：兼容。旧工作台仍可运行 draft/finalize，只是不会建立正式月份累计。
- 旧任务和历史数据如何处理：旧任务保留普通历史；仅在用户明确选择年月并完成三项人工复核后，才可迁移为候选月度快照。
- 如果框架尚未升级，模块能否继续运行：能。现有单批售后分析、人工确认和成果导出保持可用。
- 回滚方式：回滚模块 v1.3.0 提交后，框架按 capability 缺失停止调用累计入口；已发布正式成果由框架按事务记录回滚。

## 7. 验收标准

1. 给定 2026 年 1 月和 3 月正式售后快照，创建 3 月结果时允许缺少 2 月，并返回 `used_months=[1,3]`。
2. 给定跨年、重复月、乱序、目标月之后的快照或错误 SHA-256，框架不发布正式成果，并显示模块稳定错误码。
3. 替换 1 月快照后，框架重新生成 1 月以及已有的全部后续月份；任一重算失败时所有正式月份保持不变。
4. 累计重算期间没有 AI 服务请求、密钥读取或外部网络调用，且售后费用、责任工厂和投诉类型完全来自快照中的最终人工值。
5. 源码和无系统 Python 的便携运行时均可执行 `rollup`，产生累计台账、Word、品牌占比、原因占比、逐月费用、年度看板和结构化业务记录。
6. 普通售后入口继续兼容框架全局 AI 验证、售后入口跳过和默认联网策略；finalize 和累计阶段不重复联网。
7. `learning` 只在任务成为正式月份且累计事务成功后生效；替换旧月份时旧证据失效、新证据生效。
8. 未升级框架仍可执行现有 draft/finalize，公共结果 JSON 合同测试继续通过。

## 8. 备选方案与影响

- 已考虑的替代方案：在模块内直接管理正式月份数据库、历史页面、Provider 和文件事务。
- 未采用原因：会越过框架责任边界，重复实现公共存储和权限，并破坏统一合同及安全审计。
- 影响的框架目录/功能：后续由框架负责人评估；预计涉及合同、任务编排、结果存储、历史数据页面、知识库和打包。
- 影响的其他模块：同一公共月度累计合同应供水分、水煮和售后复用，但三个模块的快照 payload 与累计逻辑保持独立。
- 预计风险：替换事务中断、路径越界、旧学习证据未撤销、候选冒充正式结果。验收必须覆盖故障注入和恢复。
