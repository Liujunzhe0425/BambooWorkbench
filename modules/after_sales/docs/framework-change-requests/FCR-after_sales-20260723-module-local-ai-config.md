# 框架适配请求：售后模块页专属 AI 配置与一次启动授权

## 1. 业务目标与具体场景

售后人员一次选择 1 至 100 份售后 Excel，在同一个售后任务页配置 DeepSeek 或其他 OpenAI 兼容接口。用户点击“开始智能分析并进入人工复核”后，系统逐份分析反馈内容、方案申请明细、售后调查和最终方案，再把每份文件的售后费用、责任工厂、投诉类型等复核项集中展示；人工提交后生成汇总 Excel、图表和分析报告。

该按钮本身就是本批次的明确联网授权。业务流程不允许出现“拒绝”下拉项，也不应把内部 AI 请求 JSON 展示成业务复核内容。

## 2. 现有接口为什么不能满足

当前公共 `service_requests` 流程为每个 AI 请求注入“允许/拒绝”确认项，并在用户先填写业务复核后才调用服务。批次拆分时会出现多个授权卡片和大段 JSON，且复核人看不到 AI 建议。系统设置中的公共 AI 配置也不符合“配置入口属于售后模块”的使用要求。

模块 1.6.0 已完成直接 AI 分析、失败降级、草稿快照复用和人工值最终覆盖；仍需要框架正式接纳售后任务页专属配置和启动授权交互。

## 3. 希望增加的页面、按钮、接口或服务

- 在 `after_sales` 任务创建页显示专属配置卡：接口类型、HTTPS 接口地址、模型、API Key。
- 默认提供 DeepSeek：`https://api.deepseek.com`、`deepseek-v4-flash`、`deepseek-v4-pro`；同时支持用户填写其他 OpenAI 兼容接口。
- 主按钮文案为“开始智能分析并进入人工复核”；点击即保存配置并授权当前批次联网。
- 售后草稿任务启动时仅向模块进程传递一次性启用标记；API Key 不进入任务 JSON。
- 不为该任务创建公共 AI 服务请求，不显示允许/拒绝或请求 JSON。
- AI 失败时模块使用离线规则建议，仍进入逐文件人工复核并允许生成正式结果。

## 4. 输入、输出、状态与失败处理

- 输入：用户选择的 Excel；模块页填写的 Provider、Base URL、模型和 API Key。
- 凭据：完整配置以 JSON 保存到 Windows 凭据库的 `BambooWorkbench/after-sales-ai-config` 条目。
- 草稿输出：`service_requests=[]`；逐文件 AI 或规则建议；每份文件至少包含售后费用、责任工厂、投诉类型三项阻断复核。
- 最终输出：复用 `output-draft/after_sales_records.json` 中按文件 SHA-256 绑定的 AI 快照，不再次调用 API；人工值写入所有 Excel、JSON、报告和图表。
- 失败：配置缺失或不是 HTTPS 时不创建任务；单文件 API 超时/错误降级，不影响其他文件；损坏 Excel 保留对账失败行。

## 5. 兼容性、安全与人工确认边界

- 不改变公共任务/结果合同，旧任务仍可打开；其他业务模块的系统设置和服务请求流程不变。
- API Key 不写入配置文件、SQLite、任务目录、日志、结果、安装包或 Git，只存在 Windows 凭据库和调用时内存。
- 测试、自检和非售后任务不会读取已保存凭据；只有售后任务页的显式启动操作设置一次性启用标记。
- AI 只是候选；人工确认的费用、责任工厂和投诉类型优先级最高。未知费用保持空值，不得自动写 0。

## 6. 可操作、可复验的验收标准

1. 打开售后模块即可看到专属 DeepSeek/API 配置，系统设置不是必经入口。
2. 配置后选择脱敏样表并点击开始，待确认页不含“拒绝”“允许”或内部请求 JSON。
3. 样表 `12.06林芳梅售后申请表.xlsx` 的复核建议能呈现桃花江相关证据、3200 元费用候选、集成材责任及性能/加工原因候选；最终以人工值为准。
4. 每份 Excel 的所有复核项集中在同一条文件记录中，文件之间有清楚分隔。
5. 人工把费用改为 3200 元后，最终明细、年度汇总、分析报告和图表均使用 3200 元。
6. 100 份文件全部保留对账行；任一 API 失败不丢失其他文件。
7. 捕获任务目录、日志和输出全文，均找不到 API Key；最终阶段网络调用次数为 0。
8. DeepSeek 请求包含其 V4 思考参数；其他 OpenAI 兼容接口不包含 DeepSeek 专属字段。
9. 水分、水煮模块页面和任务行为保持不变。
10. Windows 便携版在没有系统 Python 和开发 `.venv` 时完成 draft → 人工复核 → finalize。

## 7. 模块方已完成与等待框架提供

模块方已完成：模块专属凭据读取、DeepSeek/OpenAI 兼容调用、结构化校验、逐文件降级、AI 草稿快照复用、三项必审、人工费用全输出覆盖及测试。

等待框架提供：正式审核并实现售后任务页专属配置卡、Windows 凭据保存、启动标记和页面文案；公共框架实现应由框架方独立分支提交，不应混入 `module/after-sales` 模块 PR。

## 8. 已知限制和回滚

AI 分析需要用户自备有效 API Key 和网络；不同兼容服务对 JSON 模式支持可能不同。回滚时隐藏售后专属配置卡并不设置启用标记，模块自动回到离线规则分析和人工复核，不需要迁移历史任务。
