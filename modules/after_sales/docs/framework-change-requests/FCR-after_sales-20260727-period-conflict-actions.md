# 框架适配请求：售后任务年月冲突的返回修改与取消操作

## 1. 业务目标与使用场景

用户创建售后中央月度任务后，模块会把任务目标年月与 Excel 中可确定的“提出质量问题/报修日期”比较。当目标月确定匹配为 0，继续 AI 和人工复核没有业务意义；用户应能直接返回任务页修改目标年月、重新选择文件，或取消本次任务。

售后模块 v1.3.1 已在 draft 阶段安全停止并返回稳定错误码，但模块进程不能自行改变中央任务参数或创建工作台级导航按钮，因此请求框架补充明确的恢复操作。

## 2. 当前限制

- 公共 JobRequest 的 `period_year`、`period_month` 和 `input_files` 在任务创建后由框架持有，模块无权修改。
- 公共 Module Result 可以返回 `failed`、脱敏 `errors` 和 `anomalies`，但没有声明“返回修改年月”“重新选择文件”或“取消任务”的可执行动作。
- 模块不能直接修改 `app/`、`core/`、`ui/` 或公共合同。
- 复现：创建目标 `2026-04` 的售后任务，输入只包含业务日期 `2025-05` 的脱敏样本；模块返回 `TASK_PERIOD_ZERO_MATCH`，目前只能由用户手工返回工作台重新开始。

## 3. 请求的框架改动

### 3.1 页面与交互

- 页面/区域：任务 draft 失败结果页或售后待确认入口。
- 按钮/控件：
  1. “返回修改年月”；
  2. “重新选择文件”；
  3. “取消本次任务”。
- 用户操作顺序：
  1. 框架收到售后模块 `TASK_PERIOD_ZERO_MATCH`；
  2. 展示模块已返回的脱敏目标年月、年月分布和数量；
  3. 用户选择修改年月、重新选择文件或取消；
  4. 修改后以新的任务标识重新执行 draft，不复用旧任务正式成果。
- 输入与校验：年月仍按公共 JobRequest 约束校验；文件仍由框架统一选择和授权。
- 加载、空状态、错误状态：动作失败时保留原任务失败结果，不把任务改为成功。
- 结果展示：不得显示客户名、Excel 原文、输入文件绝对路径或 Provider 凭据。
- 原型图或截图位置：无；沿用工作台现有任务表单和失败提示样式即可。

### 3.2 接口与合同

- 当前输入/输出：模块返回普通 Module Result，`status=failed`，错误码位于 `errors`，并带 `rule_id=AFTER_SALES_TASK_PERIOD_CONFLICT` 的结构化 anomaly。
- 期望输入/输出：优先由框架按稳定错误码映射 UI 动作；若框架认为需要公共合同字段，请由框架方设计通用动作合同。
- 新增或修改字段：模块方不自行发明字段。
- 示例错误：`TASK_PERIOD_ZERO_MATCH：任务目标为2026年4月，但可确定的售后业务日期中目标月匹配为0条……`
- 退出码/状态变化：模块进程仍正常完成合同写入并返回退出码 0；Module Result 保持 `failed`。
- 旧模块兼容方式：未知错误码继续使用现有失败页；只有识别该稳定错误码时显示快捷动作。

### 3.3 公共服务、存储或打包

- 所需能力：重新创建任务或取消任务的现有工作流入口。
- 调用时机：draft 返回 `TASK_PERIOD_ZERO_MATCH` 后。
- 数据保存位置：沿用框架任务存储；不得修改模块月度正式快照目录。
- 安装版/便携版要求：源码与便携版行为一致。
- 无服务或失败时的降级行为：保留现有失败页和脱敏提示，用户仍可手工回到任务页重新创建任务。

## 4. 责任边界

- 模块方已经完成：年月统计、冲突判断、零匹配前置阻断、脱敏 anomaly、稳定错误码、禁止静默改写业务日期及自动化测试。
- 等待框架提供：工作台级返回修改年月、重新选文件和取消任务动作。
- 仍由模块方负责的业务逻辑：售后日期识别、目标月匹配、正式快照过滤、费用/责任工厂/投诉类型人工确认。
- 需要人工确认的结论：部分跨月或年月未注明时，用户确认只把目标年月记录写入本月快照，并补全年月未注明日期。

## 5. 数据、安全与权限

框架只需使用任务目标年月和模块返回的脱敏计数，不应展示客户名、Excel 原文、绝对路径、API Key 或 Provider 响应。模块保持 `requires_network:false`，不读取 Windows 凭据，不直连 Provider。

## 6. 兼容性与迁移

- 是否破坏现有合同：否
- 是否兼容当前正式版模块：是；错误码映射可增量实现。
- 旧任务和历史数据如何处理：旧失败任务不迁移；用户可重新创建任务。
- 如果框架尚未升级，模块能否继续运行：能；模块返回安全、脱敏且可复验的 failed 结果。
- 回滚方式：移除错误码到动作的 UI 映射，不影响模块结果合同和历史任务。

## 7. 验收标准

1. 给定目标 `2026-04` 且已知业务日期全部不在该月的售后任务，模块返回 `TASK_PERIOD_ZERO_MATCH` 后，页面显示“返回修改年月”“重新选择文件”“取消本次任务”；
2. 点击“返回修改年月”后，原业务日期和原失败结果不被改写，用户可创建使用新年月的新任务；
3. 点击“取消本次任务”后，任务状态可识别为取消，且不创建月度正式快照；
4. 安装版和便携版行为一致；
5. 页面、日志和公共结果不出现客户名、Excel 原文、输入绝对路径或凭据；
6. 不识别该错误码的旧模块和其他模块仍使用原失败处理，不受影响。

## 8. 备选方案与影响

- 已考虑的替代方案：模块自动把任务年月改成 Excel 中出现最多的年月。
- 未采用原因：会静默改变用户选择，并可能把业务记录发布到错误月份，违反 PR #72 整改要求。
- 影响的框架目录/功能：预计为任务失败页、任务创建/取消工作流；由框架方决定具体目录。
- 影响的其他模块：如采用通用错误动作映射，可供其他模块复用；默认不改变其他模块。
- 预计风险：重新创建任务时误复用旧正式成果；验收必须确认新任务使用新任务标识且旧任务未发布快照。
