## 整改结论

1. 桌面入口不读取模块凭据，不导入或调用模块直连网关。
2. 规则抽取先完成；只有分类含糊、多标签、低置信度或根因不清的案件生成统一 `service_requests`。
3. 请求固定 `requires_user_consent=true`、`response_format=json_object`，候选编号与请求编号可重复生成并稳定绑定。
4. 请求只含限长且再次脱敏的投诉摘要、规则候选、证据编号、费用候选和必要产品上下文。
5. AI 响应只接受投诉类型、主投诉类型、原因摘要、证据引用、复核建议和置信度；出现费用、责任工厂等额外字段时整批响应拒收并降级。
6. 用户拒绝、无可用服务、超时、限流、缺失响应、非法 JSON 或非法证据引用均保留规则结果，不中断其他文件。
7. 每个成功解析的 Excel 仍固定包含“售后费用、责任工厂、投诉类型”三项阻断人工复核；AI 不能绕过。
8. 人工值最终覆盖规则/AI 候选并写入年度汇总、明细、图表、Markdown 和 JSON。

## 安全与失败边界

- 请求中不含 `customer`、`source_file`、API Key 或本地绝对路径。
- 手机号、邮箱、企业名称、常见身份标签和本地路径在模块侧先脱敏，框架仍会再次预览和脱敏。
- 严格校验响应顶层字段、候选完整性、类型枚举、置信度、证据引用和重复 JSON 键。
- `after_sales_records.json` 保留经校验的结构化 AI 建议用于审计；客户 Excel 和 Markdown 不倾倒模型原始 JSON。

## 已知限制

- 当前公共确认页的 AI 请求预览和授权交互属于框架能力；模块没有修改 `ui/` 或 `core/`。后续若要把 AI 授权与三项业务复核拆成两个页面，继续使用
  `docs/framework-change-requests/FCR-after_sales-20260722-ai-preanalysis-review.md`
  申请框架适配。
- 只处理 `.xlsx/.xlsm`；图片、扫描 PDF 仍不属于正式输入。
- 品牌没有明确原文证据时保持“未知”，不会由 AI 猜测。
