## 1. 整改结论

售后模块保留原有月度快照、年度累计、人工复核、Excel、Word、图表和完全离线累计内核，已完成中央 v1.3 月度合同薄适配。

本次修改严格限定在 `modules/after_sales/`。未修改框架、其他业务模块、`integration` 或 `main`。

## 2. 已完成项目

1. `module.json` 已声明完整 `monthly_rollup` 对象及快照、请求、响应和 learning Schema。
2. JobRequest 已接受并校验 `task_name / period_year / period_month / learning_enabled`。
3. finalize 只为任务目标年月生成单个内部快照，并通过顶层 `monthly_snapshot` 登记。
4. 内部快照不进入普通 outputs，不保存客户原文、客户身份、绝对输入路径或原始单元格。
5. 投诉类型学习描述已映射到公共 `ConfirmationPrompt.learning`；费用和自由文本责任工厂不声明为可学习字段。
6. 累计入口已适配中央 `transaction_id / snapshot_root / output_dir / configuration_identity`。
7. 快照校验覆盖 snapshot ID、job ID、模块、年月、顺序、大小、SHA-256、路径包含性、符号链接、junction 和重解析点。
8. 累计响应返回快照确认、`record_count`、全部成果 SHA-256、`network_call_count=0` 和稳定 `error {code,message}`。
9. 售后 AI 仍由框架托管，每个任务单独授权，Provider 只调用一次；finalize 和 rollup 不重复联网。

## 4. 中央真实链路

模块内真实链路测试使用售后正式 manifest 和 BAT，覆盖：

1. 未授权时拒绝创建强制 AI 售后任务；
2. 已授权后第一次 draft 生成脱敏服务请求；
3. 框架 Provider 只调用一次；
4. 第二次 draft 绑定响应并生成费用、责任工厂和投诉类型人工确认；
5. 投诉类型确认携带公共 learning 描述；
6. finalize 复用服务响应，服务请求数为零；
7. finalize 返回目标年月顶层月度快照；
8. MonthlyRunner 执行完全离线累计；
9. 框架校验成果 SHA-256 并提交正式月份槽位。

## 5. 累计与安全覆盖

- 单月累计；
- 连续月份和月份缺口；
- 早期月份替换后重新累计；
- 跨年、重复月份和乱序拒绝；
- snapshot ID、年月、大小和输入 SHA-256 校验；
- snapshot root 路径越界拒绝；
- 符号链接、junction 和重解析点拒绝；
- 输出成果 SHA-256 复算；
- 稳定小写错误码且不输出 traceback、绝对临时路径、环境变量或客户内容；
- socket 阻断情况下累计仍成功；
- 源码与冻结便携入口使用同一中央请求和响应。

## 6. 业务口径保持

- 售后费用、责任工厂和投诉类型继续逐文件人工确认。
- 月度快照和累计成果只使用最终人工值。
- 品牌、问题原因、费用、状态、Excel、Word 和图表业务生成逻辑未迁移到框架。
- v1.2.1 Excel 兼容修复和 v1.2.0 框架托管 AI 基线保持不变。
