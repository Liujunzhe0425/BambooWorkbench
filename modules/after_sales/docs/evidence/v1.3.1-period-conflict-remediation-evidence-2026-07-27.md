# 售后模块 v1.3.1 任务年月冲突整改证据

日期：2026-07-27

分支：`module/after-sales`

目标版本：`1.3.1`

整改依据：BambooWorkbench Draft PR #72 中的售后整改说明

## 1. 整改结论

售后模块已将中央任务年月与“提出质量问题/报修日期”的冲突识别从 finalize 写快照阶段前移到 draft 的 Excel 解析阶段。

目标月确定匹配为 0 时，模块在生成框架 AI 请求、普通业务确认、正式成果、学习贡献和月度快照之前立即停止。部分跨月、跨年或年月未注明时，模块显示脱敏的范围冲突信息，并要求人工确认仅把目标年月记录写入本月快照；已知业务日期不会被任务年月静默改写。

本次修改严格限定在 `modules/after_sales/`，未修改框架、公共合同、其他业务模块、`integration` 或 `main`。

## 2. 行为矩阵

| 输入情况 | draft 行为 | finalize / 快照行为 |
|---|---|---|
| 全部记录匹配目标年月 | 正常生成脱敏框架 AI 请求 | 完成人工复核后成功；快照只含目标月 |
| 同时存在目标月与其他月/年 | 生成 AI 请求；第二次 draft 增加阻断式“任务年月范围”确认 | 保留全部原业务日期；快照只含目标月 |
| 目标月确定匹配 0 条，且所有年月明确 | 立即 `failed`，错误码 `TASK_PERIOD_ZERO_MATCH` | 不进入 finalize；无正式成果和快照 |
| 年份或月份未注明 | 第二次 draft 要求人工补全日期并确认任务范围 | 补全后重新计算；仍不完整则 `TASK_PERIOD_DATE_UNRESOLVED` |
| 人工补全后仍为零匹配 | 不改写日期 | finalize 在写成果前 `TASK_PERIOD_ZERO_MATCH` |
| 任务范围确认值非法 | 不改写日期 | finalize 在写成果前 `TASK_PERIOD_SCOPE_INVALID` |

## 3. 脱敏与安全边界

年月冲突 anomaly 和错误说明只包含：

- 任务目标年、月；
- 已知年月及每月记录数量；
- 目标年月匹配数量；
- 其他已知年月数量；
- 年份未注明和月份未注明数量。

冲突说明不包含客户名称、反馈原文、解决方案原文或本机绝对路径。模块继续保持：

- `requires_network:false`；
- 不读取 Windows 凭据；
- 不读取 API Key；
- 不直连 DeepSeek 或其他 Provider；
- 第一次 draft 只生成脱敏框架 AI 请求；
- finalize 不重复申请 AI；
- 月度累计完全离线，仅复用最终人工确认值。

覆盖：

2. 部分跨月；
3. 全部跨月且目标零匹配；
4. 跨年混合；
5. 年份未注明；
6. 人工补全年月；
7. 人工填写后仍未解决；
8. 已知业务日期保持不变；
9. 快照只收录目标年月；
10. 零匹配时 AI 请求数、确认数、正式成果数和学习贡献数均为 0；
11. 冲突提示不含客户名、原文和绝对路径；
12. 源码入口和冻结便携入口行为一致。

## 6. 框架适配请求

为改善使用体验，已按正式模板提交：

`docs/framework-change-requests/FCR-after_sales-20260727-period-conflict-actions.md`

请求框架在识别 `TASK_PERIOD_ZERO_MATCH` 后提供“返回修改年月”“重新选择文件”和“取消本次任务”三个工作台级动作。模块没有越权修改框架页面、工作流或公共合同。
