## 2. 业务实现

1. `finalize` 成功且同批记录全部完成人工确认后，按报修年份、月份生成正式月度快照。
2. 快照只保存最终人工确认后的售后费用、责任工厂、投诉类型和累计所需业务字段。
3. 快照使用稳定记录键和脱敏来源名，不保存客户原文、客户身份、原始单元格或绝对输入路径。
4. 完全离线累计入口按同年、截至目标月份的正式快照生成累计台账、Excel、Word 报告、
   品牌占比、原因占比、逐月费用图和年度看板。
5. 允许月份缺口；拒绝重复、乱序、跨年、越界、SHA-256 不匹配、符号链接、junction
   和其他重解析点。
6. 替换早期月份快照后重新累计，会更新后续月份结果；重算只复用最终人工值，不调用 AI。
7. 投诉类型确认项提供稳定学习键、稳定候选值和脱敏结构化上下文。数值费用和自由文本责任
   工厂不由框架自行推断学习场景。

## 5. 文档和表格视觉复核

- 使用原生 Microsoft Word 渲染累计分析报告并逐页检查，标题、关键指标、品牌/原因表、
  月度费用、处理状态、风险提示和页脚均完整，无表格断裂或内容溢出。
- 使用工作区表格渲染工具检查累计总表、品牌占比、原因占比、月度费用、逐月案件数量和
  年度看板；公式错误扫描为 0。
- 月度费用图保留 10,000 元红色预警线，月份轴固定为 1—12 月，图例和数据标签明确。
- 全量台账不再写入会导致 Excel 修复 `xl/tables/table1.xml` 的重叠结构化表。

## 6. 安全边界

- 累计入口不导入 AI 服务适配代码，不读取 API Key、Windows Credential Manager 或
  Provider 配置。
- 快照、学习描述、累计响应和输出清单不包含密钥、Header、客户原文或绝对输入路径。
- 所有累计输出均来自月度快照中的最终人工确认值。
- 模块不修改输入文件，也不跨出框架授权的暂存目录写入累计成果。

## 7. 已知限制与框架待办

框架尚未发布精确统一的月度快照公开合同。本模块没有自行修改 `contracts/`，而是在模块
目录内提供 Draft Schema 和 FCR。合并前需要框架方确认正式月份槽位、替换事务、后续月份
重算编排、公开学习字段和历史数据页面的接入方式。
