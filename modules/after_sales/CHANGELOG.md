## 1.3.1 整改（2026-07-18）

- 第二轮仓库卫生整改：将 PR #16 脱敏输入移入 `tests/fixtures/acceptance/`，删除误提交的运行生成 Excel，只保留 Markdown、JSON 和 PNG 复验证据。
- 补充 PR #16 脱敏复验材料，包含脱敏测试夹具、Markdown、JSON、图表截图和一致性说明。
- 修复冻结运行时在 Windows GBK 控制台输出中文进度、导致工作台按 UTF-8 解码失败的问题；进度协议现在使用 ASCII 安全 JSON 转义。
- 便携运行时构建新增严格 UTF-8 逐行 JSON 验证，并覆盖工作台宿主到模块启动脚本的完整调用链。
- 修复 Windows 便携包错误调用外部 Python、因缺少 `openpyxl` 而不生成输出目录的问题；模块现在优先使用随包携带的独立运行时。
- 离线模式不再按文件生成“未配置 API”确认，字段完整且无业务歧义时直接成功。
- 将金额拆分为企业售后成本、内部责任扣款和外部承担金额，三类金额分别保存状态、依据和人工复核标记。
- 汇总改为多标签问题类型统计，同时新增每案只计一次的案件总数并写明不可把分类相加当案件数。
- Excel 新增“分析图表”，新增 `after_sales_analysis.md`，所有分析数字来自同一结构化统计结果。
- Excel、Markdown 和可外发明细 JSON 只显示文件名，不输出本机绝对路径。
- 损坏工作簿使用 `WORKBOOK_INVALID_OR_CORRUPTED` 和中文提示，保持批次文件级隔离。
- 新增整改验收回归，覆盖离线、费用分类、多标签、图表、报告、路径、损坏文件和 draft/finalize 写回。

- 新增 BambooWorkbench 模块合同适配：移除本机 Python 路径和无效清单字段，统一 `draft/finalize` 任务、进度 JSON、人工复核写回及标准 `result.json`。
- 仓库交付只包含售后处理核心、规则、模板、脱敏样本、测试和文档，不包含独立网页、日志、真实客户文件或密钥。

## 1.3.0

- 主分析页升级为 DeepSeek 智能售后数据中心视觉风格，增强标题区、模型配置、文件上传、处理流程和结果卡片的层次。

- 独立复核页统一升级为全宽双列卡片布局，强化文件、状态、原因与费用信息的可读性，同时继续保持无内部滚动区。

## 1.2.0

- “全部统计”改用完整时间轴，先按报修年份、再按月份排列；同月不同年份不再混合，年份未注明的数据单独列示。
- “输入文件对账”“售后明细”“待人工确认”同步按报修时间排序，已知年份在前，年份未注明的数据置于末尾。
- 网站主要操作文字全部改为中文，不再直接向使用者展示内部字段代码和费用状态代码。
- 人工复核拆分为独立全宽页面，本批所有文件一次铺开展示，不使用表格内部滚动框；支持逐条保存和全部保存后重新下载。

## 1.1.0

- 修复多文件总量超过 100MB 时在分析前直接返回 413 的问题；单批默认支持 200 个文件、20GB，总量覆盖一次输入 100 个 Excel 的需求。
- 上传完成后转为后台任务并提供逐文件进度查询，避免 100 个文件分析时间较长时浏览器把请求误判为失败。
- DeepSeek 遇到限流、网络超时或 5xx 时自动指数退避重试 4 次；单文件异常只标记该文件，不中断整批和其他文件导出。
- 启动器把上传临时文件、批次结果、Python 字节码和依赖缓存固定到 D 盘程序目录。
- 完成一次 100 文件、100 次模拟 API 调用的端到端压力测试：100 个输入、100 条明细、0 丢失、0 失败。

## 1.0.2
