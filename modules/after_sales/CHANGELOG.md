# 更新记录

## 1.0.2 - 2026-07-23

- 保留每份 Excel 的售后费用、责任工厂、投诉类型三项强制人工复核，所有新增图表与 Word 报告统一使用复核后的最终数据。

- 新增 `after_sales_yearly_dashboard.xlsx`：每个报修年份独立一页，上方并排放置品牌和问题原因三维饼图，下方放置 1—12 月售后反馈柱状图。

## 1.0.1 - 2026-07-23

- 售后桌面入口改用竹简工作台统一 `service_requests` 协议，不直接读取 API Key 或调用模块自带网关。
- AI 只辅助问题类型、原因摘要、证据引用和人工复核建议；费用、责任工厂和结案状态继续由规则及人工确认决定。
- 保留售后费用、责任工厂、投诉类型三项强制人工复核，并为允许、拒绝、无密钥、超时和非法响应提供离线降级。
- 最终 Excel、Markdown、JSON 和年度汇总标注 AI 辅助、离线规则或 AI 降级来源，不倾倒模型原始 JSON。

## 1.0.0 - 2026-07-22 正式版基线统一

## 1.4.0 - 2026-07-21

- 每个成功解析的售后案件固定进入一次人工复核，必审字段为“售后费用、责任工厂、投诉类型”。
- 复核页使用中文字段名并提供系统建议值；售后费用与责任工厂按文件逐条确认，禁止误用整批套用。
- `finalize` 将三项复核值写回结构化记录、“售后全量汇总表”“售后明细”和“待人工确认”审计页。
- 复核后的投诉类型只采用人工确认的主分类，重新驱动性能、外观、加工统计；复核后的费用优先覆盖规则建议值。
- “售后全量汇总表”改为匹配年度汇总参考模板：品牌/月度汇总页加逐年售后明细页。
- 明细页按受理日期排序，写入订单、销售、规格、地点、品牌、投诉原文、原因分析、处理方案、费用、责任方、分类与结案状态。
- 不同年份分开生成明细和汇总区块，避免同月份跨年混算；年份不明的记录单独保留。
- “售后费用”采用最终选择方案的实际总费用口径，同时保留三类责任金额供其他报表使用。
- 人工复核后的品牌、日期、原因、费用和结案状态会重新生成到模板同格式文件。
- 新增独立“汇总所有 Excel”年度汇总导出，不改变既有分析、复核和 `after_sales_summary.xlsx` 格式。
- 将“售后全量汇总表”登记为全局 BambooWorkbench 结果中心的首个成果，完整工作台无需修改公共框架即可直接打开。
- 新导出包含“汇总表”“售后台账”“输入文件对账”，每份输入文件固定保留一行；按提出质量问题/报修日期排序并按年份隔离统计。
- 台账并列输出客户反馈、方案申请、售后调查、解决方案、具体原因、性能/外观/加工分类、最终费用和处理状态；失败文件仍保留对账记录。

## 1.3.1 整改（2026-07-18）

- 第二轮仓库卫生整改：将 PR #16 脱敏输入移入 `tests/fixtures/acceptance/`，删除误提交的运行生成 Excel，只保留 Markdown、JSON 和 PNG 复验证据。
- 补充 PR #16 脱敏复验材料，包含脱敏测试夹具、Markdown、JSON、图表截图和一致性说明。
- 修复冻结运行时在 Windows GBK 控制台输出中文进度、导致工作台按 UTF-8 解码失败的问题；进度协议现在使用 ASCII 安全 JSON 转义。
- 便携运行时构建新增严格 UTF-8 逐行 JSON 验证，并覆盖工作台宿主到模块启动脚本的完整调用链。
- 修复 Windows 便携包错误调用外部 Python、因缺少 `openpyxl` 而不生成输出目录的问题；模块现在优先使用随包携带的独立运行时。
- 离线模式不再按文件生成“未配置 API”确认，字段完整且无业务歧义时直接成功。
- 将金额拆分为企业售后成本、内部责任扣款和外部承担金额，三类金额分别保存状态、依据和人工复核标记。
- 汇总改为多标签问题类型统计，同时新增每案只计一次的案件总数并写明不可把分类相加当案件数。
- Excel 新增“分析图表”，新增 `after_sales_analysis.md`，所有分析数字来自同一结构化统计结果。
- Excel、Markdown 和可外发明细 JSON 只显示文件名，不输出本机绝对路径。
- 损坏工作簿使用 `WORKBOOK_INVALID_OR_CORRUPTED` 和中文提示，保持批次文件级隔离。
- 新增整改验收回归，覆盖离线、费用分类、多标签、图表、报告、路径、损坏文件和 draft/finalize 写回。
