# v1.3.1 业务记录 ID 首尾空白二轮整改证据

## 问题与修复边界

框架复验发现，部分 Excel 文件在扩展名前带有尾随空格。旧实现把文件名主体原样
作为 `record_id`，导致合法月度任务在私有快照 Schema 校验阶段失败。

本轮仅修改 `modules/moisture/`：

- TaskService 工作副本序号前缀恢复后，对文件名主体执行首尾 Unicode 空白清除；
- 中文、内部空格、全角括号及其他合法业务字符保持不变；
- 不修改输入文件名、输入内容、公式、统计、规则、公共合同或累计逻辑；
- 继续拒绝 `/`、`\`、`..`、控制字符、空 ID 和超长 ID；
- 两个不同输入规范化为相同 ID 时返回
  `MONTHLY_SNAPSHOT_RECORD_ID_CONFLICT`，整批失败；
- 冲突时不采用先到先得、最后覆盖或随机后缀，不登记 XLSX、Markdown、月度快照
  和确认学习成果，输入文件保持不变。

## 覆盖场景

- 扩展名前尾随空格的真实形态中文文件；
- 文件名主体前后空格的直接解析与重复运行稳定性；
- 仅含空白的文件名主体；
- 两个不同内容文件在规范化后发生 ID 冲突，且两种输入顺序得到相同错误；
- Registry → TaskService → Runner → `run_module.bat` → draft → 年份确认 →
  finalize → snapshot → offline rollup 完整链路；
- 原有 Unicode、安全字符、路径安全、哈希和月度累计回归。
