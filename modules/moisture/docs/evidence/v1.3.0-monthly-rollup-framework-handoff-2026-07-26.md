## 1. 交接结论

水分模块已经完成 v1.3.0 的框架适配前业务内核：

1. finalize 最终业务记录的结构化月度快照；
2. 同年、截至目标月份的完全离线累计渲染；
3. 月份缺口、较早月份替换、乱序、重复、跨年、哈希和路径校验；
4. 稳定、脱敏且可回退的 confirmation 学习描述；
5. 私有 JSON Schema、脱敏示例和代表性测试；
6. 适配前模块门禁和中央合同缺口审计。

当前实现故意保持为模块私有合同，尚未接入 `module.json` capability、
`run_module.bat`、finalize artifact 或中央 `ModuleResult`。这避免模块自行发明
中央字段。框架完成 FCR 后，模块还需要执行 A-C0—A-C4 适配与联合验收，
届时才能作为正式 v1.3.0 功能在 GUI 和便携版中使用。

## 2. 已实现的模块能力

### 2.1 最终月度快照

主要实现：

- `src/moisture/contract/monthly_snapshot.py`
- `src/moisture/application/monthly_snapshot.py`
- `schemas/moisture-monthly-snapshot.schema.json`

快照只接收 finalize 后的最终业务记录，保存：

- 目标年份和月份；
- 最终样本值、最大值、最小值、区间值、均值和确定性筛查结果；
- 固定规则版本与 SHA-256；
- 已批准经验的稳定 ID、版本与内容哈希；
- 脱敏来源追溯和规范化记录 ID。

快照拒绝跨月记录、规则身份不一致、浮点数、未知字段、乱序记录、
路径越界和非原子覆盖。输出使用临时文件、`fsync` 和 `os.replace`。

### 2.2 完全离线年度累计

主要实现：

- `src/moisture/contract/monthly_rollup.py`
- `src/moisture/application/monthly_rollup.py`
- `schemas/moisture-monthly-rollup-request.schema.json`
- `schemas/moisture-monthly-rollup-response.schema.json`

累计器接收同模块、同年、唯一且有序的月度快照，重新生成截至目标月份的：

- 四工作表 `moisture_summary.xlsx`；
- 确定性 `analysis_report.md`；
- 图表成果；
- `moisture_business_records.json`；
- 带相对路径、MIME、标签和 SHA-256 的结构化成果清单。

累计重算不调用 AI、Knowledge、Provider、规则初筛、confirmation 或管理端，
也不读取旧累计输出。较早月份发生替换时，框架传入新的快照集合即可确定性重算。
允许月份缺口，但拒绝跨年、重复月份、乱序、错误哈希、缺少目标月、
晚于目标月和越界路径。

### 2.3 Confirmation 学习描述

主要实现：

- `src/moisture/contract/learning_descriptor.py`
- `src/moisture/application/learning_descriptor.py`
- `schemas/moisture-learning-descriptor.schema.json`

第一阶段只支持：

- `supplier_mapping`；
- `department_mapping`。

稳定 `learning_key` 和候选 ID 由规范 JSON 与 SHA-256 生成，不依赖 job ID、
confirmation ID、UUID、时间、绝对路径、文件名、sheet 或 source row。
上下文只保留字段、规范化材料类别和结构来源类别，并支持：

```text
字段 + 材料类别 + 结构来源类别
→ 字段 + 材料类别
→ 字段
```

其它 confirmation 类型不会生成学习描述。当前学习描述未写入正式 result，
也未改变 draft/finalize 的确认重放语义。

## 3. 保持兼容的既有能力

本次没有重新实现或破坏：

- 历史汇总追加；
- 经验管理；
- 规则管理；
- 当前规则快照；
- 水分公式和 Decimal 精度；
- 规则阈值、颜色和统计口径；
- 四表 Excel 与普通 Markdown 报告；
- 独立 AI 报告流程；
- 管理合同 v1.1。

累计输出复用既有 writer。为恢复快照中的经验引用和来源追溯，
仅对兼容模型增加缺省字段，旧调用方无需传入新值。

## 4. 需要框架实现的公开合同

唯一适配请求：

- `docs/framework-change-requests/FCR-moisture-20260726-monthly-rollup-learning.md`

框架负责人需要明确并实现：

2. finalize 成功后月度快照 artifact 的登记与受控存储；

正式模块失败时不得回退到 Mock，也不得让 AI 或学习偏好自动修改业务规则。

## 7. 框架重点复验

- finalize 只登记本月最终确认业务记录；
- draft 与 finalize 使用同一规则 `{version, sha256}`；
- 同年月份替换后只使用新快照集合离线重算；
- 累计过程不联网、不调用 AI、不产生 confirmation；
- 进程失败不登记部分成果，旧累计版本保持可用；
- 学习偏好只作用于对应模块、字段和回退层级；
- 候选值变化、偏好失效或用户清除时安全回退；
- 源码版与便携版行为一致；
- 不泄漏绝对路径、客户原始文件、供应商身份、凭据或 Provider 信息。

## 8. 当前限制

- AI 候选规则功能已经取消，不在本轮范围内。
