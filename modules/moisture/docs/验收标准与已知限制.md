# 验收标准与已知限制

> 所属模块：`modules/moisture/`
> 本文档是模块当前验收标准和已知限制的唯一权威位置。
> 业务规则细节见 `业务规则与数据说明.md`，架构与开发细节见 `架构与开发维护指南.md`。

---

## 1. 合同验收

模块必须通过 BambooWorkbench 正式模块合同 CLI 校验：

```powershell
.\.venv\Scripts\python.exe -m app.tools.module_contract_cli validate modules/moisture
```

合同验收点：

- **module.json 结构**：模块 manifest 字段完整、类型正确，Registry 可正确发现并加载；
- **Schema 锁定**：`result.json` 输出必须通过 JSON Schema（Draft 2020-12）校验，Schema 文件位于模块 `schemas/` 目录，不得在运行时动态生成；
- **BAT 启动协议**：`run_module.bat` 必须支持 `version`、`self-check` 和正式任务；`run_management.bat` 必须支持受控管理请求，退出码协议固定为 0/2/3/4；
- **artifact 清单**：普通汇总能够形成业务结果时生成四表 `moisture_summary.xlsx`、确定性 `analysis_report.md` 并最后原子写入 `result.json`；独立 AI 报告只在合法响应时生成 Markdown，降级时不得伪造报告。

| 指标 | 验收标准 | 基线结果 |

| 批次均值复核 | 逐批均值与旧系统差异为零 | 21 个批次，差异 0 |
| 阈值状态一致性 | 筛查结果与规则包定义一致 | 通过 |
| 输入文件 SHA-256 | 处理前后原文件哈希不变 | 变化 0 |
| 偏高疑似（orange） | 正确标识 | 1 |
| 偏低疑似（green） | 正确标识 | 1 |
| 正常（none） | 正确标识 | 19 |
| 异常可追溯 | 42列→19列不丢失异常明细 | 通过（原均值异常2条，新增区间值命中1条） |

筛查结果保持偏高1、偏低1、正常19。

### 2.1 XLSX 主表精简验收

`moisture_summary.xlsx` 的"竹丝含水率统计"工作表为面向业务的19列精简主表：

| 验收项 | 标准 |
| --- | --- |
| 列数 | 精确19列，表头与冻结结构一致，不含"筛查结果"文字列 |
| 冻结 | `F2`（标题行和前五列固定） |
| 筛选 | `A1:S1` |
| 材料类型 | 统一显示为"原竹丝"（展示层归一化，不修改源数据） |
| 空白样本 | 不存在样本的单元格为 Excel 空白（非0或空字符串） |
| 技术列禁止 | 主表不含批次编号、hash、规则元数据、初筛/AI/置信度/显示色/人工确认/筛查结果等技术列 |
| 颜色 | 规则命中的目标数值单元格直接染色；多条规则命中各自染色不覆盖 |
| 日期排序 | 检测日期升序；缺失回退到货日期；均缺失排最后；同日期按批次编号和文件哈希稳定 |
| 日期格式 | `yyyy-mm-dd`，不混用月日 |
| 历史业务基线 | 21批166样本的公式和统计值不变；原均值规则保持1高1低，另新增1个区间值命中 |

### 2.2 区间值筛查验收

| 验收项 | 标准 |
| --- | --- |
| `range_value > 13%` | 命中，"区间值"单元格染橙色 |
| `range_value == 13%` | 不命中 |
| `range_value < 13%` | 不命中 |
| 区间值橙色含义 | 仅表示需复核的离散程度，不是不合格、责任或处置结论 |
| 均值+区间多命中 | 两个目标字段各自染色、不互相覆盖 |
| 规则来源 | 来自规则包命中，非 writer 硬编码 |

最小验收集覆盖：正常样本、高值疑似、低值疑似、损坏文件、重复文件、11 样本工作簿，以及 draft/finalize 流程、合法 AI 响应和 denied 示例。验收命令：

```powershell
.\.venv\Scripts\python.exe -m pytest modules\moisture\tests\acceptance -q
```

## 3. 主框架真实调用验收

模块必须通过主框架完整进程闭环验收：

```text
BambooWorkbench GUI
  → ModuleRegistry（默认扫描正式 modules/）
  → TaskService（输入快照、draft/finalize）
  → ModuleProcessRunner
  → modules/moisture/run_module.bat（独立进程）
  → BambooMoistureModule.exe（portable）或仓库 .venv Python（源码开发）
  → result.json + moisture_summary.xlsx + analysis_report.md
```

验收确认项：

- Registry 正确发现并加载 moisture 模块；
- Runner 通过 `run_module.bat` 启动独立进程，非进程内调用；
- 独立进程产出完整 `result.json` 及全部 artifact；
- draft 和 finalize 使用独立 job ID，finalize 以 `parent_job_id` 重建 draft 根身份。
- 独立 AI 报告经过真实 Registry、TaskService、Runner、Provider 编排和再次 Runner finalize；
- 历史/经验选择经过真实管理服务、`run_management.bat` 和管理请求/响应合同；
- Provider 错误、超时和非法响应不生成伪 Markdown，不修改原汇总表。

### 3.1 v1.3.0 经验、规则和任务规则快照闭环验收

以下能力已经通过模块公开管理合同和主框架页面接入：

- 历史四/五表追加、SHA去重、同批冲突确认及finalize重放；
- 经验草稿、approved、retired三栏和历史复制，运行时/AI只读一致；
- 规则草稿、不可变版本、命中预览、原子发布、停用、恢复和历史复制；
- 任务按规则版本和SHA-256固定，发布新active不改变既有draft/finalize；
- managed目录损坏、快照缺失或hash不符明确失败，不回退内置资产。

模块 v1.3.0 通过 `run_management.bat manage` 提供上述能力，主框架通过版本化
`management_contract`、ManagementService/Runner 和“水分经验与规则管理”页面调用；
TaskService 在创建任务时查询并固定当前规则身份。日常操作按
[`经验与规则管理使用教程.md`](经验与规则管理使用教程.md)执行。

### 3.2 月度快照与年度累计验收

- 带正式年月的普通 finalize 生成内部月度快照，且不把快照登记为客户下载成果；
- 快照只包含最终确认后的结构化业务记录、规则身份和来源哈希；
- 公共 `rollup` 请求/响应严格符合中央 Schema，并再次校验快照大小与 SHA-256；
- 同年快照无论输入顺序如何均按月份稳定累计，重复月份、跨年、哈希错误和路径越界
  明确失败；
- 月份缺口允许存在；较早月份替换后使用新快照集合重新生成后续累计结果；
- 累计 Excel、普通报告和业务记录完全离线生成，不调用 AI、不重新发起人工确认；
- `learning_enabled=false` 时确认项不携带学习描述；启用时只提供候选、稳定键和
  脱敏回退上下文，不替代人工答案。

## 4. 便携环境与无系统 Python 验收

### 4.1 便携运行时构建

模块级构建钩子 `build_portable_runtime.ps1` 由主框架 `scripts/build_real_module_runtimes.ps1` 统一调用：

- 验证仓库 `.venv` 存在、Python 3.11+、PyInstaller 可用；
- 使用 PyInstaller **onedir** 模式构建 `BambooMoistureModule.exe`；
- 收集只读资源：schemas、rules、experience、templates、samples；
- 收集元数据文件：module.json、run_module.bat、run_management.bat、README.md、CHANGELOG.md、requirements.txt、pyproject.toml；
- 目标路径：`dist/BambooWorkbench/modules/moisture/runtime/`；
- 原子替换：`.runtime.incoming` → `runtime`，失败时从 `.runtime.previous` 回滚；
- 构建后自动清理临时构建目录；
- 缺失依赖或资源时明确报错，不自动安装全局依赖；
- 安全删除仅清理本模块构建目录和 portable runtime 产物。

### 4.2 BAT 探测优先级

`run_module.bat` 按以下优先级（从高到低）定位 Python 运行时：

1. `BAMBOO_MODULE_EXECUTABLE` 环境变量（主框架显式注入）
2. 本地冻结程序 `runtime\BambooMoistureModule.exe`
3. `BAMBOO_MODULE_PYTHON` 环境变量
4. `VIRTUAL_ENV` 环境变量（已激活虚拟环境）
5. 仓库 `.venv`
6. 模块 `.venv`

禁止裸 `python`、`py` 和系统 Python 回退。源码开发运行方式不受便携模式影响。

### 4.3 无系统 Python 验证

| 验证项 | 方法 | 验收标准 |
|--------|------|----------|
| 无 Python 环境 version | 隔离子进程调用正式 BAT | 正常输出版本号 |
| 无 Python 环境 self-check | 隔离子进程调用正式 BAT | exit 0，stderr 空 |
| portable draft | 脱敏输入，无年份合成表 | 正常产出 `needs_confirmation` |
| portable summary finalize | 默认年份确认 | 生成确定性四表，不声明 AI 复判 |
| portable AI report | 当前汇总表 + 可选历史/经验 + 合法/降级响应 | 合法响应产出独立报告，降级不伪造 Markdown |
| portable management | 导入/列举/停用历史，列举 approved 经验 | 通过独立管理 BAT 和受控数据目录 |
| finalize 身份 | 检查当前 job ID | 独立 job ID，非复用 draft |
| 输出合同 | finalize confirmations/service_requests | 均为空 |
| result.json Schema | Draft 2020-12 校验 | 通过 |
| XLSX / Markdown | artifact 存在且位于 output_dir | 通过 |
| 输入完整性 | SHA-256 前后一致 | 通过 |

## 5. 安全、路径与输入完整性验收

### 5.1 路径安全

- 仓库边界检查：拒绝路径越界操作（Assert-RepositoryPath）；
- reparse point 检测：防止符号链接/交接点绕过仓库边界；
- 安全删除仅清理本模块构建产物和 portable runtime 目录，不得影响其他模块或仓库外路径。

### 5.2 输出完整性

- artifact 写入失败不得登记半成品文件；
- `result.json` 最后原子写入，确保内容完整或不存在；
- 单文件失败使用稳定错误码（`WORKBOOK_STRUCTURE_INVALID`、`WORKBOOK_STRUCTURE_AMBIGUOUS`、`SAMPLE_LIMIT_EXCEEDED`、`SOURCE_FILE_MODIFIED`）；
- 批处理失败弹窗仅展示聚合计数，结果中心保留逐项明细。

### 5.3 输入完整性

- 输入文件始终通过主框架快照处理，原文件 SHA-256 不变；
- 提交和交付包不得包含客户原始 Excel、真实供应商身份、绝对路径、运行日志、缓存或凭据；
- XLSX 来源追溯只写文件名，不泄露开发机绝对路径。

### 5.4 stdout/stderr 协议

- stdout 仅允许进度 JSON；
- 技术诊断、traceback、错误详情进入 stderr 或日志；
- UI 不展示 traceback 或原始错误堆栈。

## 6. AI/Knowledge 降级行为

### 6.1 AI 响应处理

| 服务响应 | 降级行为 |
|----------|----------|
| 合法 AI `ok` | 独立生成 `ai_analysis_report.md` 和结构化 JSON，不修改汇总表 |
| AI `denied` | 只生成结构化 denied 结果，不伪造 AI Markdown |
| AI `error` | 只生成结构化 error 结果，不伪造 AI Markdown |
| AI `timeout` | 只生成结构化 timeout 结果，不伪造 AI Markdown |
| AI 缺失/非法响应 | 安全降级，只保留结构化原因 |
| AI 完全不可用 | 普通四表 XLSX、确定性 Markdown 和 result 仍可独立生成 |

合法 `ok` 响应必须通过 request ID、上下文哈希、结构、引用范围和文本边界校验。未知历史/经验引用或普通非结构化文本即使 request ID 匹配仍被拒绝。

### 6.2 历史与经验降级

- 未选择历史资料时允许只分析当前汇总表；
- 未选择 approved 经验时允许无经验上下文分析；
- v1.0.0 五表可只读导入，旧“模型分析记录”被忽略；
- 经验只接受 manifest 登记、哈希合法、有效期内的 approved 版本；
- 历史/经验管理失败不破坏普通确定性汇总。

### 6.3 Request ID 稳定性

- AI report request ID 绑定 draft root job ID 和规范化分析上下文；
- finalize 使用 `parent_job_id` 重建相同身份；
- 相同输入与选择重复运行产生稳定 ID；
- 真正未知的 response ID 被拒绝并安全降级。

## 7. 已知限制

### 7.1 功能范围限制

- 仅支持每个工作簿 1-10 个样本，超出上限触发 `SAMPLE_LIMIT_EXCEEDED` 错误；
- 支持标准历史汇总追加（`supports_incremental=true`）；只接受模块生成的兼容四表/五表
  历史文件，不把任意第三方工作簿当作可直接追加的标准基表；
- 不提供 Web 界面、身份认证、数据库连接、Provider 实现、HTTP 客户端或 API Key 管理；
- 不对供应商/部门映射进行猜测固化：无可靠映射时保留原值并发出 confirmation；
- 暂不穷举全部 Windows reparse point 组合。

### 7.2 文档口径与机器规则包元数据不一致

机器规则包（rule package）元数据中，`0.55` 和 `0.47` 的阈值状态记录为 `confirmed` / `default-v2-approved`。但最新业务要求这两个阈值仍处于"待业务批准"状态。该不一致属于已知状态差异，以本文档口径为准：**两个阈值当前均为待业务批准**。待业务负责人最终确认后，需统一修正规则资产元数据，使其与业务批准状态一致。

### 7.3 颜色含义

v1.3.0 当前新任务只使用确定性橙/绿，且均不是正式错误、不合格、责任或处置结论：

- 橙（orange）：确定性偏高疑似，筛查提示；
- 绿（green）：确定性偏低疑似，筛查提示；
独立 AI 报告不改变颜色。v1.0.0 旧成果中的红/蓝只读保留，不重新计算或回写。颜色的最终业务判断仍须由人工完成。

### 7.4 外部依赖

以下事项不属于模块范围，不能在模块内解决：

1. 真实 AI/Knowledge Provider 的环境部署、凭据、网络、审计和用户同意策略；
2. 正式安装器的签名、发布渠道、升级/回滚与任务数据保留政策；
3. 对外分享报告时供应商身份是否另行脱敏；
4. 新规则、新经验内容或阈值变更必须通过受治理版本发布，不能原地篡改已交付版本；
5. 主框架已支持 DeepSeek/OpenAI-compatible、Mock 和不可用 Provider；生产环境仍须完成凭据、联网和安全验收；
6. 不得把凭据放入模块、任务文件、Git 或日志。

### 7.5 测试覆盖说明

- 部分 Windows symlink 测试因当前用户缺少创建符号链接的权限（`WinError 1314`）被跳过，不是业务、合同或路径隔离缺陷；
- v1.3.0 的模块全量测试、Ruff、合同、Schema、version/self-check 和便携管理入口结果以
  当前发布线测试证据为准，不沿用旧版本的固定测试数量；
- 中央 ManagementService/Runner 已按模块 v1.1 Schema 执行前后置校验；页面仍不得直接
  import 模块内部 service 或 repository；
- GitHub Actions 若在分配 Runner 前因账户付款或 Actions spending limit 未启动，应由
  仓库负责人恢复后重跑，不得修改 expected、模块代码或 workflow 掩盖外部问题。
- 当前真实月度链仍受框架 `QProcessEnvironment` 环境复制问题阻塞；独立 AI 报告
  finalize 还会被框架错误要求提供月度快照。模块公开 BAT 合同与离线累计内核已通过，
  具体复现和最小框架修复范围见当前 FCR。
