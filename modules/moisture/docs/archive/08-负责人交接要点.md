# 竹丝水分模块负责人交接要点

## 1. 当前结论

`modules/moisture/` 已按 BambooWorkbench 正式模块合同实现。当前 integration 源码普通桌面
启动默认扫描正式模块；`--demo` 仅用于显式演示。Registry、Runner、GUI 与便携包的一致性
仍须由框架负责人完成最终复验。主框架通过 Registry → Runner →
`run_module.bat` 启动模块，模块不持有 Web、身份、数据库、Provider、HTTP 或 API Key。

已完成的负责人批准和适配：

- 当前公式、统计口径和旧模板兼容基线获批；
- `0.55/0.47` 及“竹丝/原竹丝”范围于 2026-07-17 批准为 `confirmed` 筛查规则；
- 橙/绿为确定性偏高/偏低疑似，红/蓝为严格辅助证据支持的高度疑似；所有颜色均非
  正式错误、不合格、责任或处置结论；
- 无可靠唯一供应商/部门映射时保留原值并发出 confirmation，不猜测固化；
- Knowledge 仅进入 Markdown 报告引用，不改变规则或颜色；
- 经验库运行时只读 approved 版本，离线治理端与正式运行隔离；
- XLSX 来源追溯只写文件名，不泄露开发机绝对路径；
- finalize 使用独立执行 job ID，以 `parent_job_id` 重建 draft 根身份。

## 2. 运行架构

```text
BambooWorkbench GUI
  → ModuleRegistry（默认扫描正式 modules/）
  → TaskService（输入快照、draft/finalize）
  → ModuleProcessRunner
  → modules/moisture/run_module.bat
  → BambooMoistureModule.exe（portable）或仓库 .venv Python（源码开发）
  → result.json + moisture_summary.xlsx + analysis_report.md
```

源码开发必须显式使用仓库解释器：

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print(sys.version)"
.\.venv\Scripts\python.exe -m app
```

历史工作簿只有月/日时，draft 生成一个整批共用的默认业务年份 confirmation；用户回答后，
finalize 在独立进程中以该年份重跑完整确定性管线。已有完整年份不会被批量答案覆盖。

## 3. 模块职责边界

模块负责 Excel 只读解析、公式复核、统计、规则、只读经验检索、confirmation/request
声明、响应校验、XLSX/Markdown/result 输出。主框架负责进程、任务目录、服务编排、
用户同意、Provider 和本地任务数据库。

正式运行不得 import 经验管理端；经验治理命令仅离线使用：

```powershell
$env:PYTHONPATH = (Resolve-Path "modules\moisture\src").Path
.\.venv\Scripts\python.exe -m moisture.tools.manage_experience --root modules\moisture\experience list
```

管理端支持 `list/show/create/update/validate/publish/retire`，approved 不可原地修改，
retired 保留历史文件。正式管线只查询 manifest 登记、哈希合法、在有效期内的 approved
经验；查询故障只产生降级提示，不破坏确定性输出。

## 4. 服务与离线降级

模块最多声明一个 Knowledge request 和一个 AI request，不直接调用服务。AI request
需要用户同意，候选最多 50 个，规范化 payload 不超过 65,536 UTF-8 字节并脱敏。

finalize 对 request ID、候选 ID、方向、字段、观测值、rule hash、evidence 和置信度
逐项校验。合法 AI 结构化证据才允许橙→红或绿→蓝；denied/error/timeout/缺失/非法
响应全部保留橙绿。Knowledge 只作为报告引用。服务完全不可用时仍必须输出确定性
XLSX、Markdown 和 result。

当前主框架仍使用 `MockProvider` 作为离线服务实现。真实 Provider、凭据存储、网络策略、
审计和部署配置不属于模块，启用前仍需安全/AI 负责人提供环境级方案；不得把凭据放入
模块、任务文件、Git 或日志。

## 5. 发布与 CI

计划中的 PyInstaller portable 构建应包含（以框架负责人实际打包复验为准）：

- `BambooWorkbench.exe`；
- `BambooModuleHost.exe`；
- `BambooMoistureModule.exe`；
- 正式模块 manifest、BAT、Schema、规则、经验、模板和必要源码/测试资产。

`run_module.bat` 在 portable 中优先使用主框架注入的可信模块 EXE；源码环境优先使用
已激活 `VIRTUAL_ENV` 或仓库 `.venv`，不盲选系统 Python。探测不再使用共享 `%TEMP%`、
`%RANDOM%` 或 `fc.exe`。

CI 和 `scripts/verify_repo.ps1` 应校验正式模块合同并运行模块测试；本地门禁在仓库
`.venv` 缺失或解释器不属于当前仓库时立即停止。

## 6. 用户错误与隐私

单文件失败使用稳定错误码（例如 `WORKBOOK_STRUCTURE_INVALID`、
`WORKBOOK_STRUCTURE_AMBIGUOUS`、`SAMPLE_LIMIT_EXCEEDED`、`SOURCE_FILE_MODIFIED`）。
批量失败弹窗只展示聚合计数，结果中心保留逐项明细；stdout 只允许进度 JSON，技术
诊断进入 stderr/日志且 UI 不展示 traceback。

输入文件始终通过主框架快照处理，原文件 SHA-256 不变。提交和交付包不得包含客户原始
Excel、真实供应商身份、绝对路径、运行日志、缓存或凭据。

## 7. 负责人仍需掌握的外部事项

以下不是模块缺陷，也不能在模块内解决：

1. 真实 AI/Knowledge Provider 的环境部署、凭据、网络、审计和用户同意策略；
2. 正式安装器的签名、发布渠道、升级/回滚与任务数据保留政策；
3. 对外分享报告时供应商身份是否另行脱敏；
4. 新规则、新经验内容或阈值变更必须发布新受治理版本，不能原地篡改已交付版本。
