# 框架适配请求：水分模块三功能工作台

> 本请求不阻塞moisture v1.0.0现有确定性检测。
> 本请求取代已归档的 `FCR-moisture-20260721-rule-governance-runtime-analysis`。
> 完整业务架构见：[`../architecture/moisture-next-stage-architecture.md`](../architecture/moisture-next-stage-architecture.md)。

## 1. 请求目标

请主框架为moisture提供三个清晰入口：

1. 汇总表生产；
2. AI辅助分析；
3. 规则库管理。

框架负责页面、模块数据目录、独立管理进程、任务编排、AI Provider、凭据、逐次同意和成果展示。moisture继续负责Excel、公式、统计、规则、经验适用性、AI业务请求和响应校验。

本请求不要求框架重新实现水分业务算法，也不要求修改中央Job/Result/Confirmation/Service Schema。

## 2. 当前基础

框架已经具备：

- 正式moisture Registry发现和Runner独立进程调用；
- `run_module.bat`启动及TaskService draft/finalize流程；
- DeepSeek、OpenAI-compatible、Mock和不可用Provider组合；
- Windows凭据、联网开关、脱敏预览和逐次同意基础；
- service request/response保存和确定性降级流程。

模块已经具备：

- Excel解析、公式复核、Decimal统计、五工作表输出和规则执行；
- 只读规则包加载和Evaluator；
- 经验库draft/approved/retired生命周期及离线管理服务；
- Knowledge/AI请求构建、响应严格校验和离线降级。

## 3. 请求的框架能力

### 3.1 三功能首页

moisture页面展示三个入口：

| 入口 | 用户操作 | 框架职责 |
| --- | --- | --- |
| 汇总表生产 | 创建新汇总表；历史汇总表追加新数据 | 收集文件和模式，创建正式任务，展示XLSX/Markdown/result |
| AI辅助分析 | 汇总报告分析；候选规则生成；经验指导 | 收集当前表、历史范围、经验和问题，执行同意及Provider流程 |
| 规则库管理 | 草稿、当前规则、历史版本 | 调用模块管理进程，展示校验、命中预览、发布和恢复结果 |

正式模块失败时不得静默切换为Mock，也不得绕过 `run_module.bat` 直接import模块内部业务实现。

### 3.2 版本化模块私有配置

框架根据页面选择生成模块私有配置，表达以下操作意图：

- 新建汇总；
- 历史追加；
- AI汇总报告；
- AI候选规则。

兼容要求：

- 未选择新功能时继续生成v1.0.0兼容配置；
- 只有声明支持新版私有配置的模块版本才能接收新增字段；
- 不通过“先发送未知字段、失败后降级”探测能力；
- 中央 `JobRequest` 和 `ModuleResult` Schema不变；
- 非moisture模块不接收上述私有配置。

### 3.3 轻量历史资料存储

框架在用户数据根目录为moisture提供独立数据目录。框架只负责受控路径、容量、备份和调用，不解析Excel业务内容。

模块管理进程负责：

- 校验标准汇总表或受控旧表映射结果；
- 生成稳定ID、日期范围、批次数和SHA-256；
- 创建和原子更新轻量JSON索引；
- 拒绝重复、非法Schema和路径越界；
- 将错误资料标记为retired，不原地覆盖已收录文件。

第一版不建设数据库、全文检索、多人资料管理或网络历史库。

### 3.4 独立模块管理进程

经验、历史资料和规则管理不得进入正式 `run_module.bat`。框架需要提供轻量、通用的模块管理进程宿主：

- 入口由模块私有能力声明，不能根据目录名猜测；
- 框架以独立进程调用，不import模块Python；
- 请求、响应和工作目录限制在本次管理操作目录；
- 模块数据目录作为显式授权路径传入；
- stdout只接收进度JSON，stderr保存脱敏诊断；
- 支持超时、取消、退出码和故障隔离；
- 源码模式使用仓库 `.venv`，便携模式使用随包运行时，不使用系统Python；
- 管理失败不得修改当前规则、approved经验或历史索引。

管理能力仅覆盖：

- 经验：查看、创建/修改草稿、校验、发布、停用、查看历史；
- 历史：导入、查看、选择、停用；
- 规则：查看、创建/修改草稿、校验、命中预览、发布、停用、恢复。

### 3.5 规则版本、当前指针和任务快照

框架为moisture规则管理提供模块数据目录，不解释规则字段和阈值。

模块负责创建草稿、不可变版本和当前版本指针，并采用临时文件＋`os.replace`原子切换。框架要求：

- 发布必须显示模块返回的校验、冲突提示和命中预览；
- 只有用户明确确认后才能调用发布；
- AI候选只能保存为草稿，不能直接发布；
- 已发布版本不可编辑或物理删除；
- 发布/恢复失败时旧当前版本保持可用；
- 创建正式任务时把当前规则版本、规则文件和SHA-256复制到root task只读目录；
- draft/finalize使用同一任务快照；
- 快照缺失或哈希错误时明确失败，禁止回退到新的全局当前规则。

第一版只记录本地操作人和确认说明，不宣称具备登录、角色或多人审批能力。

### 3.6 AI汇总报告

框架继续使用现有Provider和service response流程，不为moisture新增专属HTTP客户端。

页面允许用户选择：

- 当前汇总表；
- 历史资料范围；
- approved经验；
- 用户问题。

框架必须：

1. 展示模块生成的脱敏外发预览；
2. 每次联网前取得用户同意；
3. 调用当前生效Provider并生成结构化response；
4. 将合法response交给模块校验和生成产物；
5. 展示并允许打开 `ai_analysis_report.md`；
6. 展示denied、缺密钥、配置错误、HTTP错误、限流、超时和非法响应的降级原因。

API Key只保存在Windows安全凭据中，不进入模块数据、任务、数据库、日志、产物或Git。

### 3.7 AI候选规则

框架只展示模块定义的简单建议卡：规则名称、目标字段、运算符、Decimal阈值、scope、理由和限制。

框架不得：

- 提供自由代码或公式执行入口；
- 把AI文本直接写入当前规则；
- 根据AI建议自行计算命中或冲突；
- 绕过模块校验直接发布。

用户选择“保存草稿”后，由独立管理进程创建规则草稿；之后仍需模块校验、命中预览和用户确认发布。

### 3.8 经验管理

经验管理页面复用模块已有生命周期语义。框架只保存和展示模块返回的ID、版本、状态、有效期、scope和SHA-256，不重新判断经验适用性。

草稿和retired经验不得进入AI上下文。approved经验不可原地修改；修改必须创建新版本。

## 4. 安全和业务边界

- 完整Excel、原始行、绝对路径和未经允许的真实身份不得发送给AI；
- AI不能修改XLSX、确定性统计、规则命中或颜色；
- AI不能形成正式不合格、责任、处罚或放行结论；
- AI失败不能破坏确定性汇总成果；
- 正式draft/finalize不得写历史、经验或规则库；
- 管理路径拒绝 `..`、symlink、junction、reparse point和目录越界；
- 框架不得复制moisture公式、规则Evaluator、经验scope匹配或旧表字段映射；
- 下一业务版本不再由AI把橙绿升级为红蓝；历史成果保持只读。

## 5. 不请求的能力

本FCR明确不请求：

- 冻结标签数据集和复杂统计候选目录；
- 全量自动历史回放、混淆矩阵、误报率和召回率门禁；
- 复杂治理工作器操作集；
- AI自由阈值代码、组合规则或自动发布；
- 登录、角色、多级审批、多人协作平台；
- 治理数据库和在线发布服务；
- 人工复核中心或标签自动回灌；
- 新中央service类型或中央Schema修改。

## 6. 兼容和发布

- v1.0.0及不声明新能力的模块继续按现有方式运行；
- 旧任务、result和artifacts只读保留，不补写规则快照或AI报告；
- 新功能按“历史追加→AI报告→候选规则→规则管理”分阶段启用；
- 每个入口未完成时必须隐藏或明确标记不可用，不能伪装成功；
- 便携包包含获批后的页面、管理进程和模块私有Schema，但不包含客户数据、历史库、规则草稿、凭据或运行日志；
- 非moisture模块和现有中央合同保持兼容。

## 7. 验收标准

1. 默认GUI显示三个入口，并真实调用正式moisture；
2. 标准历史表可追加，旧表必须经过映射预览确认；
3. 完全重复跳过，冲突记录不自动覆盖；
4. 原历史表和输入文件SHA-256不变；
5. 历史资料存储拒绝重复、越界和非法文件，停用不物理覆盖；
6. AI外发预览不包含完整Excel、原始行、绝对路径或未授权身份；
7. 合法AI响应生成独立Markdown和结构化结果，不修改XLSX；
8. denied、缺密钥、错误、超时和非法响应均安全降级；
9. 只有有效approved经验进入AI上下文且引用可追溯；
10. AI候选只能保存为草稿，复杂表达式和未知字段被拒绝；
11. 草稿不影响正式检测，发布后仅新任务使用新规则；
12. 发布失败保留旧当前版本，恢复不删除历史版本；
13. draft/finalize规则版本和SHA-256一致；
14. 无AI、经验或历史资料时仍能生成确定性XLSX、Markdown和result；
15. API Key、客户原表、绝对路径和Provider原始响应不进入日志或交付包；
16. 其他模块和旧版本任务继续按原中央合同工作。

## 8. 责任分工

### moisture模块负责

- 历史表校验、字段映射、合并、去重和冲突业务判断；
- 轻量历史索引、经验和规则管理业务实现；
- 规则Schema、Evaluator兼容、冲突提示和命中预览；
- AI上下文、脱敏、候选建议卡和响应校验；
- XLSX、Markdown、JSON产物的业务正确性。

### 框架负责

- 三功能页面和TaskService编排；
- 模块数据目录、管理进程宿主、路径和进程隔离；
- 规则任务快照和恢复；
- Provider、凭据、网络同意、服务故障转换和成果展示；
- 便携打包、升级和框架集成测试。

### 业务负责人负责

- 批次唯一键、阈值和scope批准；
- 经验批准和规则发布确认；
- AI外发范围、报告措辞和最终人工判断。
