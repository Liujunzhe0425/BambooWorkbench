## 2. 负责人必须先知道的结论

1. 模块业务管线已经可用，真实旧格式 Excel 可以成功生成五表 XLSX 和趋势图。
2. 普通桌面启动默认 `use_mocks=True`，不会调用正式水分模块。
3. GUI TaskService 会先快照输入，并把文件改名为 `001-原文件名.xlsx`；历史文件年份只存在于原父目录时，快照会丢失年份上下文。
4. 模块已支持 `module_config_file` 中的 `default_year`，但主框架 `build_draft_job` 当前将该字段固定为 `None`。
5. `0.55/0.47` 阈值尚未批准，当前无颜色是正确治理行为。
6. 主框架 AI 编排当前使用 MockProvider；模块从不直接调用真实 API。
7. 经验只读仓储和离线治理已实现，但当前确定性管线尚未自动查询并附加经验引用。

## 3. P0：主框架正式模块启动模式

### 当前行为

```text
python -m app
→ app.__main__.main(use_mocks=True)
→ build_context(use_mocks=True)
→ Registry 扫描 mock_modules/
```

真实模块模式下，`build_context` 的 real root 是 `AppPaths.modules`，不是自动等于源码仓库 `modules/`。发布负责人需要决定正式模块的安装目录和切换方式。

### 建议方案

- 增加受支持的 `--real-modules`、配置项或部署模式；
- 正式模式扫描已安装的 real modules 目录；
- UI/诊断页面明确显示 `is_mock`、模块路径和版本；
- 生产构建不得悄悄回退到 Mock；
- Mock 继续用于演示、测试和离线服务模拟。

### 验收标准

- 普通用户能够明确选择或识别正式模式；
- Registry 显示 `module_id=moisture`、`is_mock=false`、版本 `0.1.0`；
- Runner 实际调用 `modules/moisture/run_module.bat`；
- 结果中心能打开正式 XLSX、Markdown 和 result。

## 4. P0：TaskService 快照与历史年份

### 复现

历史 Excel 内只有“4.8”“4.10”等月日，原目录为 `2026年4月份`。GUI 选择文件后：

```text
原始：2026年4月份/4.10某供应方原竹丝水分检测.xlsx
快照：tasks/<job_id>/inputs/001-4.10某供应方原竹丝水分检测.xlsx
```

模块收到快照后无法从内容或快照路径可靠知道年份，返回：

```text
WORKBOOK_PROCESSING_FAILED: WorkbookStructureError
```

这不是用户操作错误，也不应通过当前年份或文件时间猜测。

### 推荐最小修复

使用现有 JobRequest 字段 `module_config_file`，原则上不修改官方 Schema：

1. 任务创建入口允许提供模块配置；
2. `build_draft_job` 不再固定 `module_config_file=None`；
3. 任务目录生成模块配置，例如 `{"default_year": 2026}`；
4. draft 和 finalize 都传递、快照并验证同一配置；
5. 重启恢复时保持配置引用稳定；
6. UI 可提供年份输入，或提供经过校验的模块配置选择入口。

不要让主框架解析水分公式或供应商业务。主框架只负责保留/传递模块配置。

### 必测场景

- GUI → TaskService 快照 → Runner → BAT → 模块成功；
- draft/finalize 使用相同 `default_year`；
- 配置缺失、非法、越界和路径替换被拒绝；
- 完整日期不依赖 default year；
- 原文件 SHA-256 前后不变；
- 重启恢复后仍能 finalize。

## 5. P1：规则批准与颜色

当前规则包：

```text
HIGH_DEFAULT: total_average > 0.55, orange
LOW_DEFAULT:  total_average < 0.47, green
status: pending_confirmation
applicable_materials: [竹丝]
```

负责人必须取得业务书面决策：

- `0.55/0.47` 是否为生产阈值；
- “原竹丝”是否属于规则材料范围；
- 区间值是否需要规则及其阈值；
- 橙/绿初筛与红/蓝 AI 辅助语义是否接受；
- 规则版本、来源、批准人和生效时间。

未批准前不得为了“显示颜色”直接把状态改为 confirmed。规则编辑/发布工具当前不存在，运行时规则包保持只读。

## 6. P1：Knowledge、AI 与真实 API

模块已经能够声明 Knowledge/AI service request，并在 finalize 校验响应，但：

- 主框架当前默认 Provider 是 `MockProvider`；
- 真实 API Key、Provider、网络、重试、审计和用户同意都属于主框架；
- 模块不得接触凭据或直接 import HTTP 客户端；
- denied/error/timeout/非法响应必须保留确定性输出；
- 红蓝只允许由严格匹配且达到置信度门槛的结构化证据产生。

接真实 API 前必须完成安全、脱敏、同意和审计评审。

## 7. P1：BAT Python 探测的间歇风险

`run_module.bat` 当前使用 `%TEMP%` 下带 `%RANDOM%` 的临时文件验证 Python 哨兵。历史 Gate D 全量运行曾间歇出现临时探测文件占用，单项重跑通过；最近模块全量和仓库门禁均已通过。

若再次出现：

```text
No approved virtual environment provides Python 3.11 or newer and required dependency jsonschema.
```

先确认是否伴随“文件被另一进程占用”。修复必须同时满足：

- 真实验证 Python 3.11+ 和 `jsonschema`；
- 拒绝只返回退出码 0 的伪 Python；
- 不使用共享碰撞临时文件；
- 从仓库外目录启动仍成功；
- 不回退到系统 Python。

该问题属于 T21/T22 启动隔离边界，不要在打包任务中降低校验。

## 10. 经验库交接

正式运行只读取 `experience/approved/` 中 manifest 登记且有效的经验。离线管理入口：

```powershell
$env:PYTHONPATH = (Resolve-Path "modules\moisture\src").Path
.\.venv\Scripts\python.exe -m moisture.tools.manage_experience --root modules\moisture\experience list
```

管理命令包括 `list/show/validate/create/update/publish/retire`。approved 不可原地修改，修改必须创建新版本；retired 不物理删除。经验内容和证据来源由业务负责人批准。
